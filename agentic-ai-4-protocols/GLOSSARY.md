# Glossary — Agentic AI 4: Protocols — MCP, A2A, AG-UI

- **__Host- cookie** — a cookie named with the __Host- prefix; browsers accept it only with Secure, Path=/ and no Domain (lesson 31)
- **_meta** — reserved object in MCP params and results; in 2026-07-28 every request carries protocol version, client info and capabilities there (lesson 01)
- **A2A (Agent2Agent)** — the protocol between agents, which stay opaque to each other (lesson 00)
- **A2A agent** — a remote agent that another owner runs behind an Agent Card; the caller sends a message and gets a Task back, and cannot see its steps (lesson 26)
- **A2A Task** — the A2A record of one unit of work: a state (such as `TASK_STATE_COMPLETED`), its messages and its artifacts (lesson 08)
- **A2A tenant field** — the `tenant` value in an A2A request and on an agent interface in its card; the server checks it against the caller's token (lesson 38)
- **a2a-cli** — the A2A team's Go command-line client: `a2a card get <url>` fetches an agent card, `a2a send -a <url> "…"` sends a message (lesson 27)
- **A2A-Extensions** — the HTTP header that names the A2A extensions a call uses or asks for; a server that does not use them does not echo it (lesson 09)
- **A2A-Version** — the request header that names the A2A protocol version the caller uses (`1.0`); a request without it is read as version 0.3 (lesson 32a)
- **AAIF (Agentic AI Foundation)** — the Linux Foundation fund hosting MCP, A2A and other agent standards (lesson 00)
- **absolute deadline** — one fixed moment (epoch milliseconds) passed to every hop of a call chain. Each hop uses the time left, so the waits do not add up (lesson 23a).
- **Access-review table** — a printed who-can-call-what table made from the same calls that enforce the rules (lesson 39).
- **act claim** — the `act` claim of a token names the actor: who acts for the subject (`sub`). It can nest, one level per earlier actor (lesson 35)
- **AG-UI (Agent–User Interaction protocol)** — the protocol between an agent and the user's screen: a stream of events plus approval interrupts (lesson 00)
- **AG-UI event** — one typed message in an AG-UI stream, such as `TOOL_CALL_START` or `TEXT_MESSAGE_CONTENT`; related events share an id (lesson 10)
- **Agent Card** — the public JSON document an A2A agent publishes at `/.well-known/agent-card.json`: name, URL, protocol binding, skills and capabilities (lesson 08)
- **Agent Card signature** — a JWS over the card's RFC 8785 canonical JSON, with the `signatures` field left out; proves the card came from the key holder and did not change (lesson 37)
- **agent identity** — an agent's own client ID and secret, so its calls carry its own name in the logs and get only the rights its client was given (lesson 35)
- **Agent Skill** — a folder with a `SKILL.md` file: frontmatter always visible, body and supporting files loaded only when a task needs them (lesson 21)
- **AgentExecutor** — the A2A server class with `execute` and `cancel`; the SDK calls it once per incoming message, and it holds the agent's logic (lesson 08)
- **agentic AI spectrum** — chatbot → tool-using agent → multi-agent → cross-organisation; each step adds a communication line (lesson 00)
- **AGENTS.md** — a Markdown file of project rules that a coding agent reads before it works. Where several exist, the one closest to the code wins (lesson 21)
- **algorithm allow-list** — the fixed list of signing algorithms a verifier accepts (for example `ES256` only), chosen by its own policy and never taken from the token (lesson 37)
- **Allow-list** — the set of destinations the host approves in code; the model cannot add to it (lesson 30)
- **allowed_tools** — a list of tool names a host may import from a server; every other tool stays hidden (lesson 14)
- **annotations** — optional hints on a tool (`readOnlyHint`, `destructiveHint`…) set by the server; a host must treat them as untrusted (lesson 03)
- **answer key** — the list of requests with the tool and arguments each one should get; an eval scores the model's replies against it (lesson 27a)
- **approval gate** — the node in front of a write that calls `interrupt()`, so the run pauses until a person resumes it with an approve or a cancel (lesson 22)
- **Artifact** — a named output of an A2A task, made of parts, that the executor adds with `TaskUpdater.add_artifact` (lesson 08)
- **artifact back into the conversation** — the remote agent's output returned as a tool result; it can be the final answer, so the model needs no extra call to repeat it (lesson 18)
- **ASGI middleware** — a wrapper around an ASGI app that runs code before and after each request, such as opening a span or counting calls (lesson 28)
- **audience** — the `aud` claim of an access token: the resource the token was issued for. A server refuses tokens whose audience is not its own URI (lesson 15)
- **Audience (`aud`)** — the server a token is for; a server refuses any token that does not name it (lesson 39).
- **audience (aud)** — the one resource a token is meant for; a server refuses a token whose audience is another resource (lesson 37)
- **authorization code flow** — the client gets a one-time code by redirect and trades it for a token at the token endpoint (lesson 16)
- **authorization server (organisation)** — one identity provider and token issuer shared by all MCP servers of an organisation (lesson 34)
- **bearer token** — the access token sent in an `Authorization: Bearer` header; whoever holds it can use it until it expires (lesson 17)
- **bind_tools** — attaches tool descriptions to a chat model so it can reply with tool calls (lesson 01a)
- **Borderline capability** — a capability that needs one short call with model judgement; the MCP-or-A2A rule alone cannot decide it, so ownership and output shape decide (lesson 26)
- **canary cohort** — the clients that get a candidate first, picked by a stable hash of the client id, so the same client stays in the cohort as the percentage grows (lesson 32a)
- **Cancellation by closing the stream** — on HTTP a client cancels a request by closing its response stream; the server cancels the handler, which must stop work (lesson 13)
- **CancelTask** — the A2A operation that moves a task that has not ended to `TASK_STATE_CANCELED`; cancelling an ended task is an error (lesson 09)
- **capabilities** — the feature groups (tools, resources, prompts…) an MCP side says it supports (lesson 01)
- **capability (Linux)** — a fine-grained kernel power, such as binding a low port; `--cap-drop ALL` removes them (lesson 29a)
- **Capability split** — giving each agent at most two legs of the lethal trifecta, so no single agent can finish an attack (lesson 30)
- **checkpoint** — a lesson that puts a part's pieces together into one working thing you can check (lesson 02)
- **checkpoint (build)** — a lesson that joins the part's pieces into one working system and checks each requirement with a printed PASS or FAIL (lesson 22).
- **child process (subprocess)** — a program the host starts and talks to through pipes; a stdio server is one (lesson 05b)
- **Client (MCP SDK)** — the `mcp` class that connects to one server and offers `list_tools` and `call_tool`; it takes a stdio subprocess description or a server object (lesson 05)
- **client credentials** — the OAuth grant where a client authenticates as itself with its ID and secret, with no user; the token's `sub` is the client (lesson 35)
- **client ID metadata document (CIMD)** — an https client ID whose URL serves the client's name and redirect URIs; it replaces dynamic client registration (lesson 16)
- **communication line** — one kind of agent connection: to tools/data, to other agents, or to the user (lesson 00)
- **compat mode (A2A)** — `enable_v0_3_compat=True` on the JSON-RPC route: one A2A 1.0 endpoint also answers 0.3 peers (lesson 32a)
- **completion** — the `completion/complete` request that suggests values for a prompt or template argument while the user types (lesson 04)
- **Confirmation gate** — a person's yes, asked before an outbound call runs; a server's annotations do not replace it (lesson 30)
- **conformance suite** — a shared set of tests that checks a server or SDK follows the MCP spec (lesson 27)
- **confused deputy** — a proxy acts with its own authority for a stranger, because the third party trusts the proxy's client ID and the proxy does not check who asked (lesson 31)
- **container sandbox** — a process run in its own network, filesystem view and user, with limits on its kernel powers and resources (lesson 29a)
- **contextId** — the A2A id that groups the turns of one conversation; a follow-up message with the same contextId and taskId continues the same task (lesson 09)
- **controller (MCP primitive)** — who decides to use a primitive: the model for tools, the application for resources, the user for prompts (lesson 04)
- **cooperative cancellation** — `tasks/cancel` asks the server to stop; the server may finish anyway, so the final status can differ from the request (lesson 13a)
- **CORS** — Cross-Origin Resource Sharing: the headers that tell a browser which other origins may read a response. It does not stop the request reaching the server (lesson 31b)
- **CreateTaskResult** — the reply that replaces a tool result with a task handle: `resultType` `"task"`, `taskId`, `status`, `ttlMs`, `pollIntervalMs` (lesson 13a)
- **CSRF** — cross-site request forgery: a page on another site makes the user's browser send a request with the user's cookies. A bearer token in an `Authorization` header is not sent by the browser on its own (lesson 31b)
- **DatabaseTaskEventStream** — the SDK's event log in the task database; a replica reads it to stream a task another replica runs (lesson 32)
- **delegation chain** — the sequence of services a user's authority passes through, each one exchanging the token it received for one for the next hop (lesson 38a)
- **delegation tool** — a tool in the orchestrator's list whose code hands a task to another agent over A2A and returns that agent's artifact as the tool result (lesson 18)
- **deprecated roots / sampling / logging** — server-to-client features deprecated in 2026-07-28 (SEP-2577); old servers may still use them; this course does not teach them (lesson 12).
- **Deprecation header** — the reply header (RFC 9745) that gives the date a feature was deprecated (lesson 32a)
- **description length** — how many characters each tool description adds to the catalog; longer text costs more on every turn (lesson 24)
- **dual stack** — old and new behaviour served side by side on one endpoint during a migration (lesson 32a)
- **earliest removal** — the first date a deprecated feature may be removed: twelve months after it was marked Deprecated (lesson 32a)
- **egress** — network traffic leaving a process for another host; a sandbox or firewall rule controls it (lesson 29a)
- **elicitation** — a server asks the user for input during a request; delivered through MRTR in 2026-07-28 (lesson 12).
- **emit_interrupt_outcome** — the `LangGraphAgent` option that sends a LangGraph pause as the AG-UI interrupt outcome on `RUN_FINISHED` instead of a plain finish (lesson 19)
- **end-of-file (EOF) on stdin** — the signal that the other side closed its pipe; a stdio server should exit when it sees it (lesson 05b)
- **end-to-end check** — a test that goes through every hop of one user request and reads the final answer, not each hop's status (lesson 11)
- **env= (subprocess environment)** — the parameter that gives a started server the environment variables it needs, such as `TRACKR_DB_PATH` (lesson 05b)
- **era probing** — `Client(url)` in `mode="auto"` asks the server in the newest era first (`server/discover`), and falls back to the `initialize` handshake only if the server does not answer there (lesson 07a)
- **EventEncoder** — the `ag_ui.encoder` class that turns one AG-UI event into one SSE frame (`data: {json}` and a blank line) for the negotiated content type (lesson 10)
- **exact redirect URI** — the registered redirect URI compared as a whole string, never by its start (lesson 31)
- **exfiltration through arguments** — data leaving the host inside the arguments of a call the model makes to a server it should not have sent them to (lesson 29)
- **existence leak** — an answer that tells a caller something exists, by refusing it differently from a missing thing. Refusals for another tenant's data must match the answer for a missing item (lesson 38)
- **explicit state handle** — a name a request carries (an id, a cursor or a shared-store key) that lets a worker find the state; the name works only where the state is stored (lesson 07)
- **extended Agent Card** — a card with more skills, served only to authenticated callers through `GetExtendedAgentCard` (lesson 37)
- **Extension (MCP)** — an opt-in feature outside the core spec, named `vendor-prefix/name` and negotiated in capabilities; off by default (lesson 13)
- **fingerprint (pin)** — a hash of a tool's name, description, input schema and annotations, stored when a person approves it; a changed fingerprint means the tool changed (lesson 29)
- **form elicitation** — an elicitation question with a schema for structured, non-secret data; the answer goes to the server (lesson 12).
- **forwarded props** — the `forwardedProps` field of `RunAgentInput`: an application channel the protocol does not interpret, so the server must check it (lesson 31b)
- **glue code** — hand-written code joining one app to one tool in that app's own format (lesson 00)
- **google.rpc.Status** — the error envelope used by A2A; its details carry a `google.rpc.ErrorInfo` with a machine-readable `reason` and a `domain` (lesson 09)
- **Graceful degradation** — the server does the plain behaviour when a client did not opt in to an extension (lesson 13)
- **handle binding** — an export or state handle that works only for the user, and the tenant, that made it (lesson 38)
- **HeaderMismatch** — the `-32020` error a Streamable HTTP server returns when a routing header disagrees with the request body (lesson 06)
- **Health route** — a URL that a probe calls; it answers 200 only when the replica can serve, so a balancer can take it out of rotation (lesson 32)
- **host** — the app the user works in (IDE, chat app, notebook); it owns the model and runs one MCP client per server (lesson 01)
- **host config file** — the JSON file a host reads at startup to learn which servers to start (lesson 05a)
- **hosted MCP (connector)** — a vendor feature where the vendor's cloud calls your MCP server, so the server must be reachable over public HTTPS (lesson 14)
- **HTTP+SSE binding** — the AG-UI transport: a POST returns `text/event-stream` with one frame per event; no resumption, so a retry is a new run (lesson 10)
- **idempotency key** — a client-made id for one logical write. The server keeps the first result under it, and a repeat returns that result without writing again (lesson 23a).
- **ignore_localhost** — a `vcr` option: requests to localhost are not recorded or replayed, so a local HTTP server stays live while model calls are recorded (lesson 27a)
- **in-process server** — an `MCPServer` object that a client in the same Python process calls directly, with no subprocess and no transport (lesson 05)
- **Indirect prompt injection** — instructions hidden in data an agent reads from a tool, not typed by the user (lesson 30)
- **InputRequiredResult** — the reply with `resultType: input_required` that pauses a request, carrying `inputRequests` and/or `requestState` (lesson 12).
- **inputSchema** — the JSON Schema of a tool's arguments, built from the function's type hints (lesson 02)
- **Inspector exit code** — the MCP Inspector CLI's code for a failure class: 0 success, 3 auth required, 4 unreachable, 5 tool error or tool not found (lesson 27)
- **install-time consent** — the approval step where the host shows the exact command a local server will run before it starts it (lesson 29a)
- **insufficient_scope** — the error name for a valid token that lacks a scope. The server-wide `required_scopes` check answers it as HTTP `403`; a per-tool check returns an `isError` tool result (lesson 15)
- **interrupt outcome** — the `RUN_FINISHED` outcome `interrupt`: the run stopped, and it lists the interrupts a person must answer before the thread can go on (lesson 19)
- **interrupted state** — a task state that pauses the task until the client answers: `TASK_STATE_INPUT_REQUIRED` or `TASK_STATE_AUTH_REQUIRED` (lesson 09)
- **isError** — flag in a `tools/call` result: the JSON-RPC call worked but the tool itself failed (lesson 01)
- **iss (RFC 9207)** — the issuer the authorization server adds to its redirect; the client checks it to stop mix-up attacks (lesson 16)
- **JSON-RPC 2.0** — a small standard for JSON messages: requests (with `id`), results, errors and notifications (lesson 01)
- **key ring** — the list of keys for `requestState`: the first key seals, every key reads; a new key rolls in three phases, one TTL apart (lesson 32a)
- **Keycloak realm** — the tenant of one Keycloak server: its users, clients, scopes and policies (lesson 34)
- **legacy session handshake** — the old era's `initialize` request, the `Mcp-Session-Id` the server returns, and `notifications/initialized` (lesson 07a)
- **Lethal trifecta** — the three conditions for data theft in one agent: private data, untrusted content and a way to send data out (lesson 30)
- **listChanged notification** — a server event that says a list (tools, prompts or resources) changed, so the client should fetch that list again (lesson 07b)
- **localhost binding** — listening on `127.0.0.1` so only the same machine can connect to the server (lesson 06)
- **MCP (Model Context Protocol)** — the protocol between an agent and tools/data (lesson 00)
- **MCP client** — the part of a host that talks MCP to exactly one server (lesson 01)
- **MCP Inspector** — the official MCP debugging tool with a web client, a `--cli` client for scripts and CI, and a `--tui` client (lesson 27)
- **MCP server** — a program that offers tools and data over MCP (lesson 01)
- **MCP Tasks** — the extension `io.modelcontextprotocol/tasks`: a server returns a durable handle for a long tool call, and the client polls it with `tasks/get` or asks to stop it with `tasks/cancel` (lesson 13a)
- **MCP tool** — a typed function a host calls in one short request, with a name, a description, an input schema and a typed output (lesson 26)
- **MCP tool → LangChain tool** — each tool from `tools/list` becomes a LangChain tool with the same name, description and schema (lesson 01a)
- **MCP vs A2A decision** — use an MCP tool for a deterministic, schema'd function you control; use an A2A agent for work that plans, takes long, asks questions or belongs to another owner (lesson 18)
- **MCPAdapter** — LangChain's helper (`langchain.mcp`) that starts an MCP server from a config, lists its tools and runs their calls (lesson 01a)
- **mcpServers config** — the dictionary, one entry per server name, that `MCPAdapter` reads to start every server (lesson 05)
- **Message (A2A)** — one turn of talk between a client and an agent, with a role (`ROLE_USER` or `ROLE_AGENT`) and a list of parts (lesson 08)
- **messageId dedupe** — an A2A agent that stores its answer under the incoming `messageId` and returns it for a repeat. The a2a-sdk 1.2.2 does not do this for you, so this lesson's agent does it itself (lesson 23a).
- **metering** — counting requests per tool from headers such as `Mcp-Method` and `Mcp-Name`, without reading the body (lesson 28)
- **minimal environment** — the small default set of variables an MCP client gives a server process when you pass none (lesson 05b)
- **mode="legacy"** — the `Client` option that skips era probing and runs the `initialize` handshake; `mode` also takes `"auto"` or a 2026 version string (lesson 07a)
- **Multi Round-Trip Request (MRTR)** — the 2026-07-28 pattern: the server pauses a request and the client retries it, with the answers and the echoed requestState (lesson 12).
- **M×N integration problem** — M apps × N tools need M×N glue pieces without a protocol; with one, M+N (lesson 00)
- **name collision** — two servers publish the same tool name, so a merge by bare name keeps one and drops the other without an error (lesson 24)
- **namespaced tool name** — the `{server}_{tool}` name `MCPAdapter` gives each tool, so names from different servers cannot collide (lesson 05)
- **near-miss tool** — a tool whose name or description sounds like another, so a model is more likely to pick it by mistake (lesson 24)
- **noisy neighbour** — one tenant's load that slows another tenant on shared capacity (lesson 38)
- **non-resumable stream** — an event stream that cannot continue from a position after a drop. The client starts a new request or run (lesson 23a).
- **notification** — a JSON-RPC message with no `id`; nobody replies to it (lesson 01)
- **notifications/tasks** — the MCP message that pushes a full task view when the task changes, sent over a `subscriptions/listen` stream so the client need not poll (lesson 13a)
- **on-behalf-of audit** — a log line that names both the agent and the person it acted for, from the `azp`, `sub` and `act` claims (lesson 35)
- **one client per server** — each MCP client holds one connection, so it only reaches its own server's tools; a host with several servers keeps several clients (lesson 05)
- **opaque agent** — an agent you can call but not see inside: you see only its published card and its replies (lesson 00)
- **OpenAI-compatible endpoint** — a URL that accepts the OpenAI chat API for another vendor's model, such as Google's endpoint for Gemini (lesson 14)
- **OpenTelemetry (OTel)** — the open standard and API for traces, metrics and logs; the Python SDK keeps spans in memory or sends them to a collector (lesson 28)
- **Origin header** — the header a browser sets on a cross-site request, naming the page's scheme, host and port; the server can refuse origins it does not allow (lesson 31b)
- **Origin validation** — the server checks the `Origin` header of each request and refuses origins it does not list, with `403` (lesson 06)
- **orphan process** — a child process still running after the program that started it has exited (lesson 05b)
- **outputSchema** — the JSON Schema of a tool's result, built from its return type; a non-object result is wrapped under `result` (lesson 03)
- **pagination cursor** — an opaque string in a list result (`nextCursor`); the client sends it back as `cursor` to get the next page (lesson 04)
- **Part** — one piece of content in an A2A message or artifact: text, data, a file or a URL (lesson 08)
- **per-client consent** — a consent screen for each client, so one approval does not cover a new client (lesson 31)
- **per-hop audit** — one audit line at every service in a chain, each naming the caller and the actor chain, so the whole path can be read afterwards (lesson 38a)
- **per-request version negotiation** — each request names its protocol version in `_meta`; the server accepts or refuses that request alone, with no handshake (lesson 07)
- **pinned key store** — the verifier's own map from key id to public key; the card cannot change it (lesson 37)
- **PKCE (S256)** — the client sends a hash of a secret code verifier first and the verifier later, so a stolen code is useless alone (lesson 16)
- **pollIntervalMs** — the server's suggested wait, in milliseconds, between `tasks/get` calls for one task (lesson 13a)
- **POST-only endpoint** — the Streamable HTTP endpoint accepts POST only in the 2026-07-28 revision; a GET gets `405` (lesson 06)
- **process id (pid)** — the number the operating system gives a running process; `os.kill(pid, 0)` tests that it exists (lesson 05b)
- **Progress token** — an opaque `_meta.progressToken` that asks the server for `notifications/progress` events (lesson 13)
- **progressive disclosure** — loading a skill's name and description first, its body when a task needs it, and other files only when used (lesson 21)
- **project scope** — a server entry in a config file inside the repo (`.mcp.json`, `.vscode/mcp.json`, `.cursor/mcp.json`), shared through git (lesson 05a)
- **prompt (MCP)** — a reusable message template a server publishes; the user picks it and fills in its arguments (lesson 04)
- **Protected Resource Metadata** — the JSON document at `/.well-known/oauth-protected-resource/...` (RFC 9728) that names a server's authorization servers and scopes (lesson 15)
- **protocol** — a shared language with fixed rules for asking, answering and reporting errors (lesson 00)
- **protocol era** — a generation of MCP: 2025-11-25 and older use a handshake and a session; 2026-07-28 uses per-request `_meta` (lesson 07a)
- **protocol error** — a JSON-RPC `error` object with a code: the request itself was not valid, so no tool ran (lesson 03)
- **Proxy headers** — `X-Forwarded-For` and `X-Forwarded-Proto`, set by a proxy; the app trusts them only from the proxy addresses it lists (lesson 32)
- **quarantine (host)** — keeping a server's tools from the model until a person re-approves a changed fingerprint (lesson 29)
- **re-listen** — open a new subscriptions/listen stream after a drop, then refetch what you depend on; streams do not resume (lesson 07b)
- **read-only root** — a container filesystem that the process cannot write to; Docker's `--read-only` (lesson 29a)
- **reattach (SubscribeToTask)** — the A2A operation that opens a new stream on a task that has not ended, so a client that lost its connection can keep following it; the first event is the task itself (lesson 09)
- **recorded model call** — a model reply saved once in a cassette and replayed in later runs, so the same answer key gives the same score (lesson 27a)
- **red team** — running known attacks against the stack and checking the stack's outcome, not the model's words (lesson 33)
- **refresh-token rotation** — each refresh returns a new refresh token and the old one is refused after use (lesson 34)
- **remote agent as a black box** — an agent the orchestrator can call and read, but not look inside: it sees only the card and the artifact (lesson 18)
- **Replica** — one running copy of the same app; several replicas share one store and sit behind a proxy (lesson 32)
- **request** — a JSON-RPC message with an `id` and a `method`; it gets exactly one reply, a result or an error, with the same `id` (lesson 01)
- **requestState** — an opaque token the server seals and the client echoes unchanged in an MRTR retry; the server verifies it and refuses a changed one (lesson 12).
- **require_approval** — the setting that decides which tool calls need a person to approve them before they run (lesson 14)
- **Resolve / Elicit** — the Python SDK's resolver (`Resolve`, fills a tool parameter by running a function) and the question it returns (`Elicit`) (lesson 12).
- **resource (MCP)** — read-only data a server publishes under a URI; the application decides when to read it (lesson 04)
- **resource indicator** — the `resource` parameter (RFC 8707) that names the one server a token is for (lesson 16)
- **resource indicator (RFC 8707)** — the `resource` parameter that sets a token's audience to one resource server (lesson 34)
- **resource server** — an API that checks bearer tokens and never issues them. A remote MCP server is one (lesson 15)
- **resource subscription** — an opt-in in a listen request for change events on named resource URIs, such as runbook://web (lesson 07b)
- **resource template** — a resource whose URI has a variable, such as `runbook://{team}` (RFC 6570 pattern) (lesson 04)
- **resume entry** — one item of the `resume` list in a `RunAgentInput`: the interrupt id, a status (`resolved` or `cancelled`) and an optional payload (lesson 19)
- **retry as a new run** — the AG-UI rule: a dropped run is retried as a new run with a new run id and the same operation id (lesson 23a).
- **rollback (release)** — reverting a release by one setting, such as the canary percentage back to 0, with the stable version unchanged (lesson 32a)
- **Round trip** — one request and its answer; the exit test counts them per design (lesson 26)
- **routing headers** — `Mcp-Method` and `Mcp-Name`, copies of the JSON-RPC method and tool name, so a proxy can route without parsing the body (lesson 06)
- **rug pull** — a server that changes its tools or descriptions after a person has approved it (lesson 29)
- **RUN_ERROR** — the AG-UI event that ends a run which failed after its stream started; the HTTP status stays 200 (lesson 10)
- **RunAgentInput** — the AG-UI request body a client POSTs to start a run: thread id, run id, messages, state, tools, context and forwarded props (lesson 10)
- **scope** — an OAuth permission string such as `issues:read`, checked per request and per tool (lesson 15)
- **scope narrowing per hop** — each hop may keep or shrink the scope it received, never widen it; a wider request is refused (lesson 38a)
- **scope step-up** — a second authorization request for more scopes after `403 insufficient_scope`; the new scope is the union of old and new (lesson 16)
- **SDK tier** — the support level the MCP project gives each SDK; Tier 1 SDKs keep up with the spec and pass the conformance tests (lesson 27)
- **Secure MCP Tunnel** — OpenAI's way to reach a private MCP server without a public address, by tunnel id instead of server URL (lesson 14)
- **securitySchemes and securityRequirements** — the Agent Card's list of ways to authenticate (for example OAuth 2.0 client credentials) and the scopes a skill needs (lesson 37)
- **server/discover** — the MCP request every server must answer with its supported versions and capabilities (lesson 01)
- **serving legacy clients** — running one server that answers both eras, with sticky routing or the stateless legacy leg for old clients (lesson 07a)
- **session-as-tool pitfall** — passing an MCP session object as a model tool; the synchronous Gemini SDK refuses it, so use MCP-aware bindings (lesson 14)
- **ship check** — the list of named requirements that must all pass before a release, each checked by code (lesson 33)
- **single-use state** — a state value that works once and expires; a replayed callback finds nothing (lesson 31)
- **Skills over MCP** — the MCP Skills extension (`io.modelcontextprotocol/skills`): `skills/list` and `skills/get` discover skills, `resources/read` reads their files (lesson 21)
- **skills-ref** — the reference library and `skills-ref validate` command that check a skill folder against the Agent Skills spec (lesson 21)
- **span** — one timed step in a trace, with a parent span and a kind (SERVER, CLIENT or INTERNAL) (lesson 28)
- **stateless protocol** — a protocol where each request stands alone and the server keeps no session that a later request must find (lesson 07)
- **stateless_http** — the server setting that keeps no legacy session, so any worker can answer; server-to-client calls on that leg have no back channel (lesson 07a)
- **stderr** — the second output pipe, for logs; the host shows it and does not parse it as protocol (lesson 05b)
- **stdio transport** — the client starts the server as a subprocess; one JSON-RPC message per line over stdin/stdout (lesson 01)
- **StdioServerParameters** — the description of a subprocess that an MCP client starts and talks to over stdin and stdout (lesson 05)
- **stdout (protocol channel)** — the pipe that carries a stdio server's replies; any other text there corrupts the stream (lesson 05b)
- **Step-up** — a request for a wider scope that the server refuses until the user signs in again (lesson 39).
- **sticky session** — a legacy session kept in one worker's memory; its requests must reach that worker, or it answers `404 Session not found` (lesson 07a)
- **Streamable HTTP** — the MCP transport for remote servers: one endpoint, `/mcp`, where every client message is an HTTP POST (lesson 06)
- **StreamResponse** — one event of an A2A stream: a task, a message, a status update or an artifact update (lesson 09)
- **structuredContent** — the typed result of a tool call; a number or list comes back wrapped as `{"result": …}` (lesson 02)
- **subject token / actor token** — in token exchange, the subject token is the user's token being exchanged, and the actor token is the agent's token that asks (lesson 35)
- **subscriptionId** — the id of a subscriptions/listen request; the server stamps it into `_meta` on every frame of that stream (lesson 07b)
- **subscriptions/listen** — the 2026-07-28 request that opens one long-lived stream of server change events; the first frame is the acknowledgment (lesson 07b)
- **Sunset header** — the reply header (RFC 8594) that gives the date an endpoint may stop answering (lesson 32a)
- **taskId** — the id of one A2A task; a message that carries a known taskId continues that task instead of starting a new one (lesson 09)
- **TaskState** — the enum of A2A task states, all named `TASK_STATE_*` (lesson 09)
- **Teams and roles claims** — the user's groups and realm roles in the verified token, used for tenant and role decisions (lesson 39).
- **tenant** — the group a piece of data belongs to (here, a team). A shared server takes the tenant from the caller's verified token, never from a tool argument (lesson 38)
- **terminal state** — a task state that ends the task: `TASK_STATE_COMPLETED`, `FAILED`, `CANCELED` or `REJECTED` (lesson 09)
- **token bucket** — a limit that refills at a fixed rate and allows a burst up to its size (lesson 38)
- **token exchange (RFC 8693)** — the grant that trades one token for a new one with another audience or a narrower scope; the server checks both tokens (lesson 35)
- **token passthrough** — a server accepts a token not issued to it, or forwards a client's token to another API; the MCP spec forbids both (lesson 31)
- **token verifier** — the server's check of a bearer token: it returns an access token with its scopes, or nothing (lesson 15)
- **TokenStorage** — the SDK's interface for keeping tokens and client info between calls (lesson 16)
- **tool call** — a model's reply asking the host to run a tool: name, arguments and id; the model does not run it (lesson 01a)
- **tool call → tools/call** — the JSON-RPC request the host sends to run that tool (lesson 01a)
- **tool catalog** — the list of tool definitions (name, description, input schema) a host sends with each model call (lesson 24)
- **tool definition** — what the server publishes for a tool: name, title, description, input and output schema, annotations (lesson 03)
- **tool description** — the docstring the server sends with each tool; the model reads it to choose the tool (lesson 02)
- **tool error** — a normal `tools/call` result with `isError: true`: the tool ran or refused, and the model can read the text and recover (lesson 03)
- **tool poisoning** — hiding instructions in a tool's description, which the model reads and may follow (lesson 29)
- **tool shadowing** — one server's description steers the model away from, or into misuse of, another server's tool (lesson 29)
- **tool-catalog tokens** — the input tokens the catalog adds to every model call, whether or not a tool is used (lesson 24)
- **tool-selection accuracy** — the share of requests for which the model names the expected tool (lesson 24)
- **tool-selection eval** — a fixed set of requests, each scored by whether the model calls the expected tool with the expected arguments (lesson 27a)
- **ToolError** — the SDK exception a tool raises for a failure it expected; it becomes a tool error, not a protocol error (lesson 03)
- **ToolMessage** — LangChain's result of a tool run, with the `tool_call_id` of the request it answers (lesson 01a)
- **tools/list snapshot** — a committed copy of the server's tool list (names, schemas, annotations); a test fails when the live list differs (lesson 27)
- **top-level key** — the object name that holds the servers in a host file: `mcpServers` in three hosts, `servers` in VS Code (lesson 05a)
- **trace** — the whole journey of one request across services, identified by one trace id (lesson 28)
- **traceparent** — the W3C header or `_meta` key (`00-<trace id>-<parent span id>-01`) that carries trace context to the next hop (lesson 28)
- **tracing overhead** — the extra time per call that tracing adds, measured on your own calls (lesson 28)
- **Trackr v1** — the first complete Trackr: the MCP server on stdio and Streamable HTTP, a triage-agent over A2A, and an AG-UI chat endpoint that uses the MCP tools (lesson 11)
- **TransportSecuritySettings** — the SDK object that holds the allowed Host and Origin values and turns on DNS-rebinding protection (lesson 06)
- **TrustedHostMiddleware** — refuses requests whose Host header is not in the allowed list (lesson 32)
- **TTL sweep** — a scheduled delete of finished tasks older than a time to live, measured from the last update (lesson 32)
- **ttlMs** — a task's lifetime in milliseconds, counted from creation; `null` means no limit (lesson 13a)
- **UnsupportedProtocolVersionError** — the spec error, JSON-RPC code `-32022`, for a version the server does not support; its `data` lists the supported versions (lesson 07)
- **untrusted input** — any value the client sends, including state, messages, tools, context and forwarded props; the server checks it against a rule before use (lesson 31b)
- **URL elicitation** — an elicitation that sends the user to a web page for a secret (password, payment, OAuth login), so the secret never passes through the client or the model (lesson 12).
- **url entry** — a config entry with a `url`, telling the host where a remote server is (lesson 05a)
- **user scope** — a server entry in your own home-folder config, used in every project (lesson 05a)
- **vendor SDK client** — an MCP client shipped by a model vendor (such as the OpenAI Agents SDK) that runs in your process and drives the agent loop (lesson 14)
- **VersionedDatabaseTaskStore** — the SDK's SQL task store that gives each task a version, so replicas can detect a concurrent write (lesson 32)
- **well-known path** — a fixed URL path under `/.well-known/` where a server publishes a document that clients always look for; the A2A card uses one (lesson 08)
- **wire tap** — a transparent middleman that forwards and logs every JSON-RPC message between host and server (lesson 01a)
- **worker** — one process that answers MCP requests; several workers can run behind a load balancer, each with its own memory (lesson 07)
- **WWW-Authenticate challenge** — the header on a `401` or `403` reply that says how to get a valid token and names the metadata URL (lesson 15)
- **X-Accel-Buffering** — a response header that tells nginx not to buffer the response; event streams send it so frames arrive as they are written (lesson 32)
