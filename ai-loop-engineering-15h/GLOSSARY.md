# AI loop engineering (15-hour course) glossary

- **accepted baseline** — the golden score a reviewer accepted from a green run, committed as a file; the CI gate reads it and never rewrites it (lesson 17)
- **advisory budget** — a limit the model is told about (for example "3 turns left") that nothing enforces; it can help planning but does not stop the run (lesson 05)
- **agent loop** — the model, tool, observation cycle inside one run, repeated until the model stops asking for tools (lesson 01)
- **approval gate** — a named step where the loop pauses, shows the real arguments, and continues only on a person's answer; nothing before the gate may write (lesson 22)
- **argument schema** — the pydantic class that names and checks one tool's arguments (types, patterns, minimum values); the model reads the same rules as JSON (lesson 04)
- **audit trail** — append-only rows for every tool call and decision, each with its run, actor chain and bundle id; a trigger refuses edits (lesson 30)
- **Backoff** — waiting longer after each failed try (for example, about 1 s, then 2 s, then 4 s), so a struggling service gets room to recover (lesson 13).
- **begin immediate** — a SQLite transaction that takes the write lock at BEGIN, before it reads; a second writer that asks for the lock gets "database is locked" while the first holds it (lesson 20)
- **budget** — the set of caps for one run (turns, tokens, dollars, time) and the counters that track them; `None` switches a cap off (lesson 05)
- **call budget** — a fixed number of model calls for one run, retries included, counted in one place; the loop stops when it is spent (lesson 18)
- **checker** — a separate judge call with fresh context: it reads the spec and the diff, never the maker's chat, and answers pass or fail (lesson 14)
- **checkpointer** — a saved copy of the loop's state, written after each step, so a new process can resume where the last one stopped; this course's SQLite table is the simple form (lesson 12)
- **CI gate** — a pytest run in continuous integration that replays the golden set from recorded model calls and fails the build when a case turns red or the pass rate falls below the accepted baseline (lesson 17)
- **Circuit breaker** — a guard that stops calls to a service after repeated failures and fails fast for a cool-down period (lesson 13).
- **clearing tool results** — replacing an old tool result in the chat history with a short marker, so later calls stop resending it; no model call (lesson 15)
- **cognitive surrender** — a reviewer stops checking and accepts an agent's output without reading it (lesson 19)
- **compaction** — replacing old turns of a chat with a short summary that the model writes; costs one call and loses detail (lesson 15)
- **Compose `--scale`** — starts N copies of one service in Docker Compose; `--wait` returns when they report healthy (lesson 28b)
- **comprehension debt** — the team cannot explain or change code that was merged faster than people read it (lesson 19)
- **context engineering** — deciding what the model can see in its window for one call or run (lesson 01)
- **dollar cap** — a `max_usd` limit on the spend of one run, summed from each reply's token counts and the price (lesson 05)
- **durability** — when LangGraph writes a checkpoint: `sync` before the next step (the drill uses it), `async` (the default, written while the next step runs), `exit` only at the end (lesson 26a)
- **enforced budget** — a cap your code checks and acts on, stopping the loop whatever the model says (lesson 05)
- **error_max_turns / error_max_budget_usd** — Agent SDK result subtypes reported when `max_turns` or `max_budget_usd` is reached; `is_error` is true (lesson 10)
- **escalation** — the loop's hand-off to a person when it cannot finish: a reject or an unclear answer, too many holds, or a step cap close to the end (lesson 22)
- **exit (of a run)** — one of four ways a run ends: done, stuck, over budget or hand off. The stop reason says why the loop stopped; the exit says what happens next (lesson 06)
- **exit code (pytest)** — the number a test run returns: 0 when every test passed, 1 when some failed, other values when the run itself broke (lesson 07)
- **fail closed** — a gate that blocks the finish when it cannot decide, so an error in the gate itself never lets red work through (lesson 10)
- **feature list** — a JSON file of items, each with a `passes` flag, written only after the verifier has run; it records progress for a person or a new session, and the loop's to-do list still comes from pytest (lesson 12)
- **fenced merge** — a merge into main that checks the owner and attempt of the lease in the same write transaction, so a stale run's approval is refused (lesson 24)
- **fenced write** — a write that checks the owner, the attempt and the lease in the same transaction, so a stale worker is refused (lesson 28b)
- **fencing token** — the attempt number a lease hands out; a write that carries an old token is refused, so a stale worker cannot overwrite a newer owner (lesson 20)
- **flat state** — a state fingerprint that does not change over several steps, a no-progress signal for write loops (lesson 06)
- **fresh context per iteration** — each loop turn starts with only what its item needs (the module, its test, its failing lines), not the whole earlier chat; state lives in files or a database (lesson 09)
- **gate (tool boundary)** — plain code that decides run, hold, skip or stop before each tool call; the model cannot change it (lesson 19)
- **git worktree** — a second working folder linked to one repo, with its own branch and files; one per loop run so runs cannot overwrite each other (lesson 21)
- **global stop flag** — the one row (`stop_all`) that every worker reads; while it is on, no worker claims a run and running runs stop at their next check (lesson 26b)
- **goal-based loop** — a loop that keeps going until a success condition is met or a turn cap is reached; Claude's `/goal` is one (lesson 09)
- **golden set** — a fixed list of cases with known good ends, run on the whole loop after every change; a falling score is a regression (lesson 07)
- **grant list (run grant)** — the named set of tools one run may call, written in code and fixed before the run starts (lesson 23)
- **hand off** — passing an unfinished case, with its evidence, to a person instead of retrying (lesson 06)
- **handoff** — passing a task or result from one agent to another; only what the sender writes down survives it (lesson 25)
- **harness engineering** — designing that environment so one run can do its job safely (lesson 01)
- **harness** — one run's environment: tools, permissions, sandbox and context around the model (lesson 01)
- **heartbeat** — a timer that wakes a loop on a fixed beat to scan for work; also a worker's renewal of its lease while it runs (lesson 20)
- **hook (PreToolUse)** — code the agent runs before each tool call; it returns an empty dict to allow the call or a `permissionDecision` of `deny` with a reason to refuse it (lesson 16)
- **Idempotency key** — a unique key sent with a write; the provider returns the first result for a repeat with the same key instead of writing again (lesson 13).
- **identical-call check** — a stop rule: the model asks for the same call (same tool, same arguments) three times in a row (lesson 06)
- **inner loop** — the agent loop inside one run (lesson 01)
- **intent debt** — code does what the prompt said, not what the team meant, and the meaning is written nowhere a later run can read (lesson 19)
- **interrupt()** — the LangGraph call that pauses a run at a node, saves its state to the checkpointer and returns the value shown to the reviewer; on resume the node runs again from its first line (lesson 22)
- **Jitter** — a random part added to a retry wait, so many clients do not retry at the same instant (lesson 13).
- **kill switch** — one flag that every worker reads at the top of each iteration; setting it stops the runs it covers (lesson 26b)
- **lax mode (pydantic)** — pydantic's default validation: it converts some inputs to the field type, for example the string `"20"` to the number 20.0. `strict=True` turns the conversion off (lesson 04)
- **lease takeover** — when a lease expires, another worker claims the run with the next attempt number; the claim is one transaction, so only one worker wins (lesson 26b)
- **lease** — a claim on a task with an owner, an attempt number and an expiry time; it must be renewed, or it expires and another worker may take the task (lesson 20)
- **least privilege** — give each run only the tools and amounts its job needs, so a fooled model has nothing dangerous to call (lesson 23)
- **lethal trifecta** — private data, untrusted text and an outside action in one agent; the Rule of Two keeps at most two without a person (lesson 19)
- **LLM-as-judge** — a model that grades another model's answer when no deterministic check exists; it needs its own calibration against human labels before it is trusted (lesson 07)
- **loop engineering** — designing the system that triggers, checks, retries, stops and resumes many agent runs, so a person does not drive each turn (lesson 01)
- **maker** — the agent call that proposes a change; a maker never grades its own change (lesson 14)
- **max_budget_usd** — Agent SDK limit on the client-side cost estimate in US dollars, checked after each response, so one response can overshoot it (lesson 10)
- **max_turns** — Agent SDK limit on tool-use round trips; default unset (lesson 10)
- **MCP server** — a separate process that offers tools, prompts or resources over the Model Context Protocol, so any MCP client can use them; this course only chooses it (lesson 16)
- **mechanical gate** — a program that decides "done" from a deterministic check, such as the goal's tests, not from the model's words (lesson 10)
- **merge queue** — the step that lands worker branches into `main` one at a time, so each merge is checked against the latest `main` (lesson 25)
- **message role** — the label on each message in a model call: `system` (the rules), `user` (the request), `assistant` (what the model said before) (lesson 02)
- **Model fallback** — moving to a second model when the first one raises an error (lesson 13).
- **model-judged goal** — a stop condition an evaluator model judges from the conversation, such as `/goal`; weaker than a program's check for anything a test can verify (lesson 10)
- **no-progress detection** — the checks that stop a loop repeating without progress: identical calls, the same error twice, a flat state (lesson 06)
- **observation** — the text your code returns for a tool call; the model reads it on its next turn (lesson 03)
- **orchestrator-worker** — one agent plans and writes a brief per item; workers each run one item with a fresh context and return a result (lesson 25)
- **outer loop** — the system around the agent loop: trigger, goal, verifier, state and stop rules (lesson 01)
- **overshoot** — the spend past a cap caused by the reply that crossed it; caps are checked after a reply, so one reply can always overshoot (lesson 05)
- **pass^k** — the chance that all k independent runs succeed (p to the power k, for a per-run chance p); it measures reliability, not one lucky run (lesson 07)
- **Per-hop timeout** — a deadline on one network call, so a hung request ends and does not hold the whole loop (lesson 13).
- **per-run cancel** — a flag on one run; the run ends `cancelled` at its next check while the other runs keep going (lesson 26b)
- **planted bad change** — a deliberate break in a candidate that the eval gate must block, to prove the gate works (lesson 30)
- **pocket-cart** — the course's generated Python shop repo: six modules, 18 tests, 12 failing; the loop fixes it under pytest (lesson 07)
- **premature completion** — the model says the task is done while the verifier still lists failures; a loop stops on the verifier's empty list, never on the claim (lesson 11)
- **proactive loop** — a loop started by an event or a schedule, with no person in real time; each task exits when its goal is met (lesson 09)
- **progress file** — a plain-text log, one line per iteration, that the next session reads at its start (lesson 12)
- **progressive disclosure** — showing a skill's name and description up front and loading its full body only when the model asks for it (lesson 16)
- **prompt caching** — the API reads a repeated input prefix at a lower price; the prefix is still input, so the context does not get shorter (lesson 15)
- **prompt engineering** — designing the words of one request to a model (lesson 01)
- **prompt injection** — text in data (a review, a web page, a tool result) that tries to give the model new instructions; the model cannot reliably tell it from the real ones (lesson 23)
- **prune** — the checkpointer call that deletes old checkpoints so the table does not grow without limit (lesson 26a)
- **Ralph loop** — Geoffrey Huntley's outer loop: one item per iteration, fresh context each time, tests as backpressure, commit on green (lesson 11)
- **recursion_limit** — the step cap in a LangGraph run's config (a top-level key); a run that reaches it stops with `GraphRecursionError`; the library default is 1000 (lesson 22)
- **regression gate** — a check in CI that blocks a change when the golden score falls below the last accepted score (lesson 07)
- **RemainingSteps** — a LangGraph managed state value: the steps left before `recursion_limit`, so a node can give up cleanly before the run raises an error (lesson 22)
- **replay** — running a graph again from an older checkpoint; the steps after it run again, so every side effect on the way needs a key (lesson 26a)
- **restart-safe run** — a loop that reads its finished cases from the repo's history and skips them, so a restart makes no model call for them (lesson 18)
- **review bandwidth** — how many diffs a person can read well in a day; the limit on how many agents a loop can usefully run (lesson 25)
- **review slots** — how many finished branches one reviewer reads at a time; the rest wait in a review queue (lesson 21)
- **review window** — how long a run parked at an approval gate keeps its lease while a person decides; an answer after the window is refused and the task returns to the queue (lesson 24)
- **reward hacking** — an agent satisfies the check instead of the goal, for example by editing the test so it asserts nothing (lesson 14)
- **RPM** — requests per minute, one of a provider's limits (per project, not per key); the lab uses a 10-second window (lesson 28b)
- **Rule of Two** — until injection can be reliably detected, a session should hold at most two of: untrusted input, sensitive systems or data, the power to change state or talk outside (lesson 23; Meta, 2025-10-31)
- **SELECT ... FOR UPDATE SKIP LOCKED** — a Postgres row lock: a worker takes the next free row and skips rows another worker already holds (lesson 26a)
- **shift** — one loop run over the inbox that stops at its cap; the findings it did not reach wait for the next shift (lesson 30)
- **SIGKILL** — the signal that stops a process at once, with no cleanup code; a power cut or an out-of-memory kill does the same (lesson 26a)
- **skill (SKILL.md)** — a folder `.claude/skills/<name>/` with a `SKILL.md` file: YAML frontmatter (name, description) and instructions the model loads on request (lesson 16)
- **spine** — the fixed spec every iteration starts from (here `FIX_PLAN.md`); the loop reads it and never edits it (lesson 12)
- **state fingerprint** — a hash of everything the tools can change, compared from one step to the next (lesson 06)
- **Stop hook** — a command or prompt that Claude Code runs when the agent tries to finish; exit code 2 (or `"decision": "block"`) keeps the agent working with the stderr as the reason (lesson 10)
- **stop reason** — why a run ended: `answered` (the model replied in text) or `turn_cap` (your counter stopped it) (lesson 03)
- **stop_hook_active** — hook input that is true when the agent is already continuing because a Stop hook blocked it; a gate must not use it to let red work finish (lesson 10)
- **streaming** — receiving the model's reply in chunks while it is written, instead of waiting for the whole reply (lesson 02)
- **stuck** — a stop reason: a no-progress rule fired and the loop stopped before its next paid call (lesson 06)
- **subagent roll-up** — adding a subagent's tokens and dollars to the parent's totals, so the parent's caps cover the whole tree (lesson 05)
- **Temporal** — a durable workflow engine for runs that wait for days, with timers and history replay at fleet scale; Go deeper, not in this course (lesson 26a)
- **tenacity** — the Python retry library: backoff, jitter and a stop rule as decorator settings (lesson 28b)
- **thread_id** — the key that names one run's saved state in a checkpointer; a resume must pass the same one, or the run has nothing to load (lesson 22)
- **time cap** — a `max_seconds` limit on the wall-clock time of one run, checked after each reply (lesson 05)
- **time-based loop** — a loop that reruns on an interval or a schedule, such as `/loop 5m` or a cloud routine (lesson 09)
- **token cap** — a `max_tokens` limit on the total tokens (input plus output) of one run, summed over its replies (lesson 05)
- **token** — a small piece of text the model reads and writes, roughly three-quarters of an English word; usage and price are counted in tokens (lesson 02)
- **token multiplier** — how many more tokens a design uses than one chat turn; about 4x for one agent and about 15x for a multi-agent research system (Anthropic) (lesson 25)
- **tool call** — the model's request to run one named tool with arguments; your code runs it and returns the result (lesson 03)
- **trajectory check** — a check on how a loop reached its end (a test edited, the turns used, a repeated failure), not only on the final answer (lesson 17)
- **Transient error** — an error where the same call may succeed later, such as a 503 or a timeout; the only kind a loop retries (lesson 13).
- **triage inbox** — the table of findings that a heartbeat scan writes and workers take, one row per finding (lesson 28b)
- **trigger** — what starts a run: a schedule (cron tick, heartbeat), an event (webhook, new ticket) or a queue message; a trigger starts work but does not decide who does it (lesson 20)
- **turn cap** — the maximum number of model calls one run may make, counted in your code (lesson 03)
- **turn-based loop** — the loop a person drives, one prompt per turn, until the model judges the task done (lesson 09)
- **usage** — the token counts a model returns with each reply (`usage_metadata`: input, output, total); cost is computed from it (lesson 02)
- **validation error** — the failure a schema check raises when a tool call's arguments break a rule; the tool body never runs (lesson 04)
- **verifier digest** — a hash of the verifier files, taken before the maker runs; a changed digest means the verifier was edited (lesson 14)
- **verifier files** — the files the check depends on (the tests and pytest.ini); the maker must not write them (lesson 14)
- **verifier** — the check that decides whether a result is done; deterministic where possible (lesson 01)
- **workflow** — code decides the steps and the model fills in one of them; fixed and testable (lesson 01)
- **write guard** — a rule that refuses a model proposal that writes a verifier file (lesson 18; the rule itself is from lesson 14)
