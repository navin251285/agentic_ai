# Glossary — Agentic AI 7: Computer-use, coding and long-horizon agents

- **accessibility role** — what an element is for assistive technology (`textbox`, `button`, `combobox`, `link`); the first word of each aria-snapshot line, followed by the accessible name (lesson 08)
- **accessibility tree** — the roles and names of a page's elements as assistive technology sees them; text, compact, blind to canvas and pixels-only content (lesson 02)
- **action** — a tool call the model proposes and the harness runs to change the environment (lesson 01)
- **action dispatch** — the harness step that checks a model's tool call against the latest snapshot and turns it into a real call (`fill`, `select_option`, `click`) (lesson 09)
- **action set** — the fixed list of actions a computer-use tool offers; Claude's `computer_toolset_20260801` has 17 member tools, each switchable with `configs` (lesson 13)
- **action space** — the set of actions a harness accepts (clicks at points, element refs, keys, shell commands, code); each needs a matching observation (lesson 03)
- **agent loop** — the repeated cycle observe → decide → act, run by the harness until the model stops or a limit is hit, followed by verification (lesson 05)
- **agentic harness** — the layer around a model that provides its tools, manages the context it sees, runs the loop and keeps the transcript; products differ mostly here (lesson 15)
- **ai mode** — `aria_snapshot(mode="ai")`: an aria snapshot made for models, with an element ref (`[ref=e12]`) on every element and `[cursor=pointer]` on clickable ones (lesson 08)
- **aria snapshot** — Playwright's YAML text form of the accessibility tree, from `page.aria_snapshot()` (lesson 02)
- **base64** — a text encoding of binary data, 4/3 the original size; how images travel inside API requests and recorded cassettes (lesson 10)
- **batch action** — several computer-use `tool_use` blocks in one reply, run in order; the first failure stops the rest, which get a fixed halt text (lesson 13)
- **browser agent** — an agent whose observations come from a web page (aria snapshots here) and whose actions are browser actions (click, fill, select) run by the harness (lesson 12)
- **browser context** — an isolated profile inside one browser process, with its own cookies, storage and pages; cheap to create, so one per task (lesson 07)
- **bug reproduction** — following a bug report's steps on the real application and observing the actual result, so the bug is confirmed before anyone fixes it (lesson 14)
- **code action** — code the harness runs with the environment in scope; one action can do many steps and needs the API, not the screen (lesson 03)
- **coding agent** — an agent that searches, edits and tests a code repository (lesson 00)
- **compounding error** — run success falls as p^n because every step must work; small per-step error rates multiply into likely failure over long tasks (lesson 04)
- **computer-use agent** — an agent that observes a screen or web page and acts with clicks, typing and keys (lesson 00)
- **computer-use tool** — a vendor-defined tool whose actions (screenshot, click, type, ...) the model is trained on; the harness runs them on a real screen and returns results (lesson 13)
- **coordinate action** — an action aimed at a pixel position, such as a click at (x, y); it needs a screenshot and is valid only for that screenshot (lesson 03)
- **course map** — the parts and lessons of this course and how Pocket Tracker grows through them (lesson 00)
- **CSS pixel** — the page's own unit of length; viewports, `bounding_box()` and `page.mouse.click` all use it, whatever the screen's density (lesson 11)
- **device scale factor** — device pixels per CSS pixel (`window.devicePixelRatio`, 2 on Retina-style screens); a screenshot is the viewport times this factor unless taken with `scale="css"` (lesson 11)
- **DOM** — the browser's full model of a page; as raw HTML it includes tags, attributes, styles, scripts and hidden elements (lesson 02)
- **downscaling** — resizing an image to fewer pixels before sending it, to fit a model's size limits or a token budget; it saves tokens and makes text smaller (lesson 10)
- **element reference** — a short id (`e6`) a snapshot gives each element so an action can name it instead of pointing at pixels (lesson 03)
- **environment** — the system an agent changes (a tracker, a browser page, a repo); it holds the real state (lesson 01)
- **evidence capture** — the harness saving what the agent saw at every step (an aria snapshot and a screenshot) to files, so a verdict can be checked and reviewed later (lesson 14)
- **gather context / act / verify** — the three phases of a coding agent's loop: find and read the relevant code, change it, check the change by running tests or the program (lesson 15)
- **glob** — a path pattern such as `**/*.py` (`**` = any depth); a glob tool lists the files whose paths match, without reading them (lesson 16)
- **grep** — searching file contents for a pattern and returning matching lines with file and line number (Claude Code `Grep`, Gemini CLI `grep_search`) (lesson 16)
- **GUI grounding** — mapping what an agent wants to click to a point on the screen; a main failure point of vision agents (lesson 11)
- **harness** — the code around the model that runs its tool calls and returns the results (lesson 00)
- **headless browser** — a full browser that renders pages and runs JavaScript but draws no window; used on servers, in CI and by agents (lesson 07)
- **health check** — a cheap endpoint such as `/health` that is polled after start-up to know a server is ready (lesson 06)
- **hit-testing** — finding which element's box contains a clicked point (lesson 03)
- **image tokens** — the tokens a model charges for an image, computed from its pixel size by a vendor formula (Claude: `ceil(w/28)*ceil(h/28)`), not from file size or content (lesson 10)
- **local environment** — everything an agent needs running on your own machine (127.0.0.1), with no accounts or network, so runs repeat exactly (lesson 06)
- **locator** — Playwright's description of how to find an element (`page.locator("aria-ref=e12")`, `page.get_by_role(...)`), resolved only when you act on it (lesson 09)
- **long-horizon agent** — an agent that works over many steps or sessions, so it needs notes, checkpoints and stop rules (lesson 00)
- **measurement limit** — the point past which too few, too costly test tasks make a measured success rate or time horizon too noisy to trust; above ~16 h for METR's horizons (lesson 04)
- **minified file** — a generated file with whitespace removed, often all on one line; one grep hit in it can flood the context (lesson 16)
- **normalised coordinates** — a point given on a fixed grid independent of image size (Gemini: 0-999); convert with `x / 1000 * width` (lesson 11)
- **observation** — what the harness shows the model of the environment, such as a text view, an aria snapshot or a screenshot (lesson 01)
- **observation cost** — the tokens one observation adds to every model call, multiplied by the number of steps in a run (lesson 02)
- **observation-action loop** — the agent loop where every step starts from a fresh observation, and an action that may change the page ends the step (lesson 12)
- **outcome verification** — deciding success by checking the environment's final state against a definition of done written before the run, never by the model's report (lesson 05)
- **output truncation** — cutting a tool result to a size limit (characters per line, results, lines) and telling the model what was left out and how to get more (lesson 16)
- **page** — one tab inside a Playwright browser context; `goto`, `go_back`, `title` and `locator` work on it (lesson 07)
- **Playwright** — a library that drives Chromium, Firefox and WebKit from code; in Jupyter use its async API with top-level `await`, in a plain script the sync API (`sync_playwright`) or `asyncio.run` (lesson 07)
- **progress note** — a short file a long-running agent writes so a later session can continue (lesson 00)
- **re-snapshot** — taking a fresh observation after acting, to see the real outcome before the next step (lesson 09)
- **recorded run** — a saved agent run (model replies in an llm_replay cassette, plus what the environment showed) that replays exactly with no key and no cost (lesson 12)
- **repro steps** — the actions that reproduced a bug, written by role and name instead of refs, so they replay in a fresh browser without a model (lesson 14)
- **scratch repo** — a disposable git copy of the code that agents change; `git reset --hard` and `git clean -fdx` restore it (lesson 06)
- **screenshot** — the page as pixels, a vision model's observation; its token cost depends on image size, not content (lesson 02)
- **seeded bug** — a bug put into a test application on purpose, with steps to reproduce, so the correct fix is known (lesson 06)
- **stale element** — an element ref from an older snapshot or a page that has since reloaded or navigated; it matches nothing and must be refused, then re-observed (lesson 09)
- **step limit** — a harness cap on model calls and on actions per run, so a run that does not converge stops and does limited damage (lesson 05)
- **step reliability** — the chance that one agent step (one action and its result) works (lesson 04)
- **test application** — a small app built for agents to work on, with known content, known bugs and tests, so results can be checked (lesson 06)
- **time horizon (50%)** — the length of task, in skilled-human working time, that a model completes with 50% success; METR's measure (lesson 04)
- **tool categories** — the groups a coding agent's tools fall into: search, file operations, execution, web, code intelligence, plus orchestration (lesson 15)
- **tool version** — the dated name of a vendor tool (`computer_toolset_20260801`, earlier `computer_20251124`); it fixes the message shape and which models accept it (lesson 13)
- **transcript** — the saved record of an agent run: every message, tool call and tool result in order (Claude Code: JSONL under `~/.claude/projects/`) (lesson 15)
- **triage** — giving an issue a label, a priority and a comment without fixing or closing it (lesson 05)
- **turn cap** — the maximum number of model turns the harness allows before it stops the loop (lesson 01)
- **viewport** — the visible area of a page in CSS pixels, set per browser context; a screenshot has the viewport's size times the device scale (lesson 10)
- **windowed file view** — a tool that shows a numbered slice of a file (e.g. up to 100 lines) and says where the slice sits and how to read on (lesson 16)
- **zoom (computer-use action)** — returns one region of the screen at full resolution so the model can read small text without a bigger screenshot every step (lesson 13)
