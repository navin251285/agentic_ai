# Glossary — Agentic AI 1: LLM foundations and the agent loop

- **`Annotated`** — a type hint with extra data attached, e.g. `Annotated[str, "one word"]`; lesson 27 uses the extra data as the parameter's description for the model (lesson 27)
- **`asyncio.gather`** — runs several awaitables concurrently and returns their results in the order they were passed in (lesson 25)
- **`asyncio.to_thread`** — runs a plain (blocking) function in a worker thread so it can be awaited alongside coroutines (lesson 25)
- **actionable error message** — an error text that says what was wrong and what a valid call looks like, e.g. "Retry with just a name, e.g. 'mars.txt'" (lesson 28)
- **agent loop** — call the model; if it asks for a tool, run it and add the result to the history; repeat until it answers or a limit is hit (lesson 01)
- **agent** — a model running in a loop that can call tools, read their results and decide when it is done (lesson 01)
- **API error** — the server rejected a call; the SDK raises an exception with an HTTP status (4xx: fix the request, 5xx: retry) (lesson 13)
- **API key** — a secret string that identifies you (and who pays) to a model provider; kept in an environment variable, never in code (lesson 07)
- **autoregressive generation** — producing text by predicting one token, appending it, and feeding the longer text back in (lesson 02)
- **backend** — the object a chat loop calls for the model (`count`, `stream`); swapping a real one for a scripted fake lets the same loop be tested with no key (lesson 18)
- **bigram model** — a toy language model that predicts the next token from only the previous token, using counts (lesson 02)
- **BPE tokenizer** — byte-pair encoding: starts from characters (or bytes) and repeatedly merges the most frequent neighbouring pair into a new token (lesson 03)
- **call id** — an id your own code makes for each model call and logs, so failures are findable even when the provider gives none (lesson 13)
- **cancellation** — ending an agent run on request from outside the loop, e.g. a Stop button setting a `threading.Event` the loop checks at each step (lesson 30)
- **candidate** — one possible reply inside a Gemini response; by default there is exactly one (lesson 07)
- **chat loop** — a loop that reads a user line, appends it to the history, sends the history to the model, appends the reply and repeats until the user quits (lesson 06)
- **checkpoint** — a lesson where you build something from everything in the Part so far, with requirements, a test and a reference solution (lesson 06)
- **chunk** — one piece of a streamed reply; in Gemini a full response object holding only the new text (lesson 11)
- **constrained decoding** — at each step the server removes every token that would break the schema before sampling, so the output always fits it (lesson 20)
- **context rot** — model accuracy and recall get worse as the number of tokens in the context grows, even below the limit (lesson 05)
- **context window exceeded** — a request that does not fit: usually a 400 error ("prompt is too long"), or a reply stopped early (lesson 05)
- **context window** — the most tokens a model can handle in one request: system prompt, history, new input and the output it writes, including thinking (lesson 05)
- **conversation history** — the list of messages your code keeps and resends each turn; it is the only memory a chat has (lesson 06)
- **coroutine** — what calling an `async def` function returns: paused work that runs only when awaited or scheduled on the event loop (lesson 25)
- **cost-latency-quality trade-off** — no model is best at price, speed and answer quality at once; pick the cheapest, fast-enough model that passes a written check for the task (lesson 17)
- **count_tokens** — a provider call that returns how many input tokens a request would use, without generating; Gemini's is `client.models.count_tokens` (lesson 12)
- **cumulative chat cost** — the running total over a conversation; because history is resent, it grows roughly with the square of the number of turns (lesson 12)
- **data-first ordering** — putting long input data at the top of a prompt and the instructions or question at the end (lesson 19)
- **dated price table** — per-model prices per million tokens with the date each became valid, plus when and where someone last checked them (lesson 17)
- **developer role** — OpenAI's name for system-level instructions (a `developer` message or the `instructions` parameter); same rank as a system prompt (lesson 08)
- **disable parallel tool use** — asking the model for at most one tool call per turn: Anthropic `disable_parallel_tool_use`, OpenAI `parallel_tool_calls=false`, Gemini only by instruction (lesson 25)
- **dispatch table** — a dict from tool name to function, used to run the tool the model named (lesson 27)
- **encoding (tiktoken)** — a named, trained tokenizer such as `o200k_base` or `cl100k_base` (lesson 03)
- **end of turn** — a model reply with no tool calls: the final answer, and the normal way the agent loop ends (lesson 26)
- **end token** — a special token that marks the end of a text; when the model picks it, generation stops (lesson 02)
- **environment variable** — a named value the operating system gives a running process; read with `os.environ`; `load_dotenv` fills it from a `.env` file (lesson 07)
- **error as observation** — a tool failure is caught and sent back to the model as the tool's result, so the model can change its next call instead of the run crashing (lesson 28)
- **error result** — a tool result marked as a failure, carrying a short message (exception type and text, no stack trace) (lesson 28)
- **eval** — a fixed set of inputs plus a checker that scores a model's outputs, used to compare prompts or models (lesson 19)
- **event loop** — the asyncio scheduler that runs coroutines and switches between them whenever one is waiting (lesson 25)
- **exit test** — a checkpoint's final demonstration; in lesson 18, showing that forgetting comes only from what is in the request: history not resent, or trimmed to fit the window (lesson 18)
- **exponential backoff** — waiting `base x 2^attempt` seconds after each failed attempt, up to a cap (lesson 14)
- **fake model** — a scripted Python function that stands in for a real model, so the loop runs and tests without a key (lesson 01)
- **few-shot examples** — a handful (3 to 5) of sample inputs with correct outputs placed in the prompt, so the model copies the pattern (lesson 19)
- **field validator** — a `@field_validator` method on a Pydantic class that checks or changes one field and raises `ValueError` to reject it (lesson 21)
- **finish reason** — Gemini's name for the stop reason: why the model stopped writing (`STOP`, `MAX_TOKENS`, ...) (lesson 07)
- **greedy decoding** — always picking the highest-probability next token (lesson 02)
- **hallucination** — fluent model output that states something invented or false (lesson 02)
- **high-signal result** — a tool result holding only what helps the next step (ids, short text, totals), not a raw dump (lesson 29)
- **instruction hierarchy** — the trained priority order a model follows: vendor policy, then system/developer instructions, then the user, then tool or document text; behaviour, not a guarantee (lesson 08)
- **is_error flag** — a marker on a tool result saying the tool failed: `is_error: true` on an Anthropic `tool_result`, an `"error"` key in a Gemini `FunctionResponse.response` (lesson 28)
- **jitter** — randomness added to a retry wait so clients do not retry together; full jitter picks between 0 and the backoff (lesson 14)
- **JSON mode** — an API setting (`response_mime_type="application/json"` on Gemini) that guarantees valid JSON but not which keys or types it holds (lesson 20)
- **JSON Schema** — a standard JSON format for describing the shape of JSON data: types, properties, required keys, allowed values (lesson 20)
- **logit** — the raw score a model gives each possible next token before softmax turns it into a probability; can be negative (lesson 04)
- **loop detection** — stopping an agent run when the model makes the same tool call (same name and arguments) more than an allowed number of times (lesson 30)
- **malformed function call** — Gemini's finish reason when a tool call could not be completed, e.g. cut off by the token limit; there is nothing to run (lesson 13)
- **max output tokens** — the limit you set on how many tokens the model may write in one reply (`max_tokens`, `max_output_tokens`); thinking tokens count toward it (lesson 05)
- **max_tokens truncation** — a reply stopped by the output limit; the text is real but unfinished (lesson 13)
- **merge (BPE)** — one learned rule "glue piece a and piece b into ab"; a BPE tokenizer is an ordered list of merges (lesson 03)
- **message-list validity** — the rules a history must follow to be accepted: not empty, known roles, system first, no empty text, last message from the user (lesson 08)
- **model family** — one vendor's models of the same kind in several sizes (for Gemini: flash-lite, flash, pro); bigger is usually smarter, slower and more expensive (lesson 17)
- **model pinning** — fixing an exact model id (not a `-latest` alias) in one config place, so behaviour and cost change only when you change it (lesson 17)
- **model_version** — the Gemini response field naming the model that actually answered; compare it with the id you pinned (lesson 17)
- **monotonic clock** — a clock that only moves forward (`time.monotonic()`), safe for measuring durations even when the system time is corrected (lesson 30)
- **next-token prediction** — the one job of a language model: given the text so far, give a probability to every possible next token (lesson 02)
- **nucleus sampling** — another name for top-p sampling (lesson 04)
- **pagination** — returning results one page at a time with a total and a next-page marker, so the model asks for more only when needed (lesson 29)
- **parallel tool calls** — several tool calls in one model reply, each with its own tool call id; all their results go back in one message (lesson 25)
- **parse helper** — an SDK feature that takes a class (e.g. a Pydantic model), sends its schema and returns a typed object (`resp.parsed` in google-genai) (lesson 20)
- **path traversal** — escaping a folder with names like `../x` or absolute paths; stopped by resolving the path and checking the real parent (lesson 29)
- **pause_turn** — Anthropic stop reason: a server-run tool loop paused at its limit; send the reply back to continue (lesson 13)
- **per-call timeout** — a limit on one model request (`types.HttpOptions(timeout=ms)` in google-genai), so a hung call raises instead of blocking the loop (lesson 30)
- **poka-yoke** — designing a tool so misuse is impossible or harmless, e.g. clamping a page size or refusing paths outside a folder (lesson 29)
- **prefill** — starting the model's reply for it with a final assistant turn; rejected with a 400 error on Claude 4.6 and later (lesson 19)
- **price per million tokens (per MTok)** — how providers quote prices, separately for input and output; cost = tokens × price / 1,000,000 (lesson 12)
- **prompt engineering** — writing and testing the text you send a model so its output is reliably what your code needs (lesson 19)
- **Pydantic validation** — checking data against a Pydantic class's types and rules; failures raise one `ValidationError` listing every broken rule (lesson 21)
- **rate limit** — a provider's cap on requests or tokens per time window; exceeding it returns HTTP 429 (lesson 14)
- **refusal** — the model declines to answer; Anthropic reports `stop_reason: "refusal"` (lesson 13)
- **renormalise** — divide the kept probabilities by their total so they add up to 1 again (lesson 04)
- **request id** — the provider's id for one API call, used for support tickets and log searches (lesson 13)
- **request trimming** — dropping the oldest user/assistant pairs from the request (not from the stored history) until it fits the window minus the reserved output (lesson 18)
- **response object** — what an API call returns: the reply text plus metadata such as model version, id, finish reason and usage (lesson 07)
- **retry before first chunk** — retrying a streamed call only while nothing has been shown; after that, a retry would repeat text the user has already seen (lesson 18)
- **retry cap** — the maximum number of attempts before a retry loop gives up and raises, bounding cost and time (lesson 21)
- **retry-after** — a response header giving the seconds to wait before retrying (lesson 14)
- **role prompt** — a line, usually in the system instruction, that tells the model who it is and whom it works for (lesson 19)
- **role** — the label on each message saying who wrote it: `user`, `model` (Gemini) or `assistant` (most vendors), or `system`/`developer` (lesson 08)
- **RPM / TPM** — requests per minute and tokens per minute, the units of rate limits (Anthropic splits TPM into ITPM and OTPM) (lesson 14)
- **safe evaluation** — computing a model-supplied expression by walking its syntax tree with an allow-list of operations, never `eval` (lesson 29)
- **safety block** — the provider withholds a prompt (`prompt_feedback.block_reason`) or a reply (finish reason `SAFETY` and similar); `.text` is `None` (lesson 13)
- **sampling** — picking the next token at random, weighted by its probability, instead of always the top one (lesson 04)
- **schema from type hints** — building a tool's JSON Schema from a Python function's parameters, type hints, defaults and docstring instead of writing it by hand (lesson 27)
- **schema subset** — the part of JSON Schema a vendor's structured output supports; keywords outside it are rejected, and the subset differs per vendor (lesson 20)
- **SDK client** — the vendor library object (e.g. `genai.Client`) that holds your key and settings and turns Python calls into HTTP requests (lesson 07)
- **server-sent events (SSE)** — an HTTP response that stays open and sends `data: ...` lines, one event per blank-line-separated block; content type `text/event-stream` (lesson 11)
- **sliding window (truncation)** — dropping the oldest messages so the rest fits; done by apps or by you, not by most APIs by default (lesson 05)
- **softmax** — turns logits into probabilities: exp of each score divided by the sum of all of them (lesson 04)
- **spend cap** — a monthly spending limit; Anthropic returns 429 `enforced_spend_limit_reached` with no retry-after, so retrying is futile (lesson 14)
- **stateless model** — a model whose reply depends only on the messages in the current request; it remembers nothing between calls (lesson 06)
- **step limit** — the most steps (`max_steps`) the agent loop may take before it stops without an answer and reports `stop="step_limit"` (lesson 26)
- **step** — one pass of the agent loop: one model call plus the tools it asked for (lesson 26)
- **stop condition** — the rule that ends generation: end token, max_tokens limit, or a stop sequence (lesson 02)
- **stop reason** — why a reply ended (`end_turn`, `max_tokens`, `stop_sequence`, `tool_use`, `pause_turn`, `refusal`); Gemini calls it finish reason (lesson 13)
- **stop sequence** — a text given in advance; generation stops when it appears, and it is left out of the output (lesson 02)
- **stopping condition** — a rule that ends the agent loop (end of turn, step limit, timeout, repeated call, cancel); the run reports which one as `stop` (lesson 30)
- **streaming** — receiving a model's reply in small pieces while it is still being generated, instead of all at once at the end (lesson 11)
- **structured output** — model output in a machine-readable shape (here JSON) that code can use directly (lesson 20)
- **subword token** — a token that is part of a word; rare words are split into several of them (lesson 03)
- **system instruction** — the developer's standing rules for the model, sent with every request outside the chat turns; Gemini `system_instruction`, Anthropic `system` (lesson 08)
- **temperature** — divides logits before softmax; below 1 sharpens the distribution, above 1 flattens it; 0 means greedy (lesson 04)
- **thinking tokens** — hidden reasoning tokens a reasoning model writes before its answer; they use the output budget and are billed as output (lesson 05)
- **thought signature** — an opaque field Gemini 3 attaches to function-call parts; send the model's turn back unchanged or the request fails with a 400 (lesson 22)
- **thundering herd** — many clients retrying at the same moment and overloading the server again (lesson 14)
- **time to first token (TTFT)** — the time from sending the request to receiving the first piece of the reply; what users feel as waiting (lesson 11)
- **token bucket** — a rate limiter that refills continuously, so bursts can be rejected below the per-minute limit (lesson 14)
- **token id** — the number for a token in the vocabulary; models read and write ids, not text (lesson 03)
- **token** — the unit of text a model reads and writes (lesson 02 uses words and punctuation; lesson 03 shows real tokenizers) (lesson 02)
- **tokenizer differences** — each model family (and sometimes each version) has its own tokenizer, so the same text has different token counts (lesson 03)
- **tokens per second** — how fast the model writes once it has started: output tokens divided by the time from first to last chunk (lesson 11)
- **tool call id** — the id the model gives each tool call; the matching tool result must carry the same id (not lesson 13's call id) (lesson 22)
- **tool call** — a model reply that asks your code to run a named tool with given arguments; the model runs nothing itself (lesson 22)
- **tool design** — shaping a tool for the model as its user: one job, a clear name and description, narrow inputs, small results, actionable errors (lesson 29)
- **tool registry** — one object that holds every tool's function and schema; tools are added with a decorator and the loop reads from it, so adding a tool needs no loop change (lesson 27)
- **tool result** — the message your code sends back with a tool's output, tagged with the tool call id it answers (lesson 22)
- **tool schema** — the description of a tool sent to the model: name, description and a JSON Schema for its arguments; Gemini calls it a FunctionDeclaration (lesson 22)
- **tool** — an ordinary function your code runs when the model asks for it by name with arguments (lesson 01)
- **tool-definition token cost** — the input tokens every tool schema adds to every model call, whether or not the tool is used (lesson 29)
- **top-k** — keep only the k most likely tokens, renormalise, then sample (lesson 04)
- **top-p** — keep the smallest set of most likely tokens whose probabilities add up to at least p, renormalise, then sample; also called nucleus sampling (lesson 04)
- **truncation (tool results)** — cutting a result past a size limit and saying so in the result, with how to ask for less (lesson 29)
- **usage accounting** — reading the token counts each response reports (input, output, thinking) and turning them into cost per turn and per conversation (lesson 12)
- **usage fields** — the token counts a response reports (input, output, thinking, total); the basis of cost (lesson 07)
- **validation context** — extra data passed with `model_validate_json(..., context=...)` that validators read as `info.context`, e.g. the source note (lesson 21)
- **validation retry** — sending the model its invalid reply plus the validation errors and asking again (lesson 21)
- **ValidationError** — Pydantic's exception; `.errors()` gives one dict per problem with `loc`, `type`, `msg` and `input` (lesson 21)
- **vocabulary** — the fixed list of tokens a tokenizer knows, each with a number (token id) (lesson 03)
- **wall-clock timeout** — a limit on the real time a whole agent run may take, checked between steps (lesson 30)
- **worst-case turn cost** — exact input cost plus `max_output_tokens` at the output price; an upper bound you can check before sending (lesson 12)
- **XML tags (in prompts)** — labels like `<note>` and `<example>` that mark where each part of a prompt starts and ends (lesson 19)
