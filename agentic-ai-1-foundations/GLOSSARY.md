# Glossary — Agentic AI 1: LLM foundations and the agent loop

- **429 Too Many Requests** — the HTTP status for "slow down"; temporary unless it is a spend cap (lesson 14)
- **529 overloaded** — Anthropic's `overloaded_error`: the API as a whole is too busy; temporary, retry with backoff (lesson 15)
- **acceptance check** — a test the finished program must pass; in lesson 35, `check_scout` runs five scripted runs: the happy path, a raising tool, an unknown tool, a path outside the folder and the step limit (lesson 35)
- **actionable error message** — an error text that says what was wrong and what a valid call looks like, e.g. "Retry with just a name, e.g. 'mars.txt'" (lesson 28)
- **adapter contract** — the rules every model adapter's reply must meet (role `assistant`, text or tool calls, string call ids, dict args), checked on every reply by `check_reply` (lesson 37)
- **agent** — a model running in a loop that can call tools, read their results and decide when it is done (lesson 01)
- **agent loop** — call the model; if it asks for a tool, run it and add the result to the history; repeat until it answers or a limit is hit (lesson 01)
- **`Annotated`** — a type hint with extra data attached, e.g. `Annotated[str, "one word"]`; lesson 27 uses the extra data as the parameter's description for the model (lesson 27)
- **API error** — the server rejected a call; the SDK raises an exception with an HTTP status (4xx: fix the request, 5xx: retry) (lesson 13)
- **API key** — a secret string that identifies you (and who pays) to a model provider; kept in an environment variable, never in code (lesson 07)
- **approval gate** — a tool runner that holds a side-effecting call until a human approves, edits or rejects it; a rejection comes back as a tool error (lesson 52)
- **asynchronous job** — work you submit and check on later by polling its state, instead of waiting for the reply in the same call (lesson 42)
- **`asyncio.gather`** — runs several awaitables concurrently and returns their results in the order they were passed in (lesson 25)
- **`asyncio.to_thread`** — runs a plain (blocking) function in a worker thread so it can be awaited alongside coroutines (lesson 25)
- **atomic write** — write to a temporary file, then rename it over the old one (`os.replace`), so a crash leaves the old or the new file, never half of one (lesson 39)
- **audit record** — an append-only entry saying who decided what about which tool call, when, and with which arguments it actually ran (lesson 52)
- **automatic function calling (AFC)** — google-genai's SDK helper: pass Python functions as tools and the SDK runs each call and loops, up to `maximum_remote_calls` (default 10) (lesson 44)
- **autoregressive generation** — producing text by predicting one token, appending it, and feeding the longer text back in (lesson 02)
- **backend** — the object a chat loop calls for the model (`count`, `stream`); swapping a real one for a scripted fake lets the same loop be tested with no key (lesson 18)
- **baseline throughput** — Vertex AI's tokens per minute per model that a usage tier is sized for; traffic above it is served best effort (lesson 56)
- **batch API** — an endpoint that accepts many model requests at once (often a JSONL file), runs them later, and returns all results together, at a discount (lesson 42)
- **batch discount** — the lower price for batched requests; 50% of the standard input and output price at Gemini, Vertex, Anthropic and OpenAI (lesson 42)
- **benchmark** — a fixed set of questions, a fixed scorer and a fixed harness, run once per configuration so that only the configuration changes between runs (lesson 45)
- **bigram model** — a toy language model that predicts the next token from only the previous token, using counts (lesson 02)
- **BPE tokenizer** — byte-pair encoding: starts from characters (or bytes) and repeatedly merges the most frequent neighbouring pair into a new token (lesson 03)
- **broken stream** — a streamed reply that did not reach its final `message_stop` (error event, dropped connection); its partial text is thrown away before retrying (lesson 15)
- **budget reservation** — taking a run's maximum spend from a shared budget before the run starts and refunding the unused part after, so concurrent runs cannot all see the same balance (lesson 55)
- **burst factor** — the busiest minute's traffic divided by the average minute of the peak hour (lesson 56)
- **burst headroom** — spare capacity kept above the busiest expected minute, e.g. never planning above 70% of a tier (lesson 56)
- **busiest minute** — the highest-traffic minute you expect; the number to compare with a rate limit, not the average (lesson 56)
- **cache breakpoint** — a marker (Anthropic `cache_control`) saying "cache the request up to here"; at most 4 per request (lesson 41)
- **cache hit rate** — cached input tokens divided by all input tokens, measured from each response's usage (Gemini `cached_content_token_count`, Anthropic `cache_read_input_tokens`) (lesson 41)
- **cache prefix** — the part of a request, from the first token up to a breakpoint, that is stored and matched exactly; order is tools, system, then messages (lesson 41)
- **cache TTL** — how long a cache entry lives without use: 5 minutes by default on Anthropic (refreshed on each hit), 1 hour for a dearer write (lesson 41)
- **call id** — an id your own code makes for each model call and logs, so failures are findable even when the provider gives none (lesson 13)
- **call id matching** — the rule that every tool call is answered by exactly one result carrying its id, placed right after the call; Anthropic rejects breaks with a 400, Gemini `generate_content` on Vertex accepted them silently (lesson 23)
- **canary** — sending a small, fixed share of users (chosen by hashing the user id) to a new model before everyone; rollback sets the share to 0 (lesson 53)
- **cancellation** — ending an agent run on request from outside the loop, e.g. a Stop button setting a `threading.Event` the loop checks at each step (lesson 30)
- **candidate** — one possible reply inside a Gemini response; by default there is exactly one (lesson 07)
- **capacity maths** — turning measured per-run numbers and demand guesses into tokens per minute, concurrency and monthly cost before launch (lesson 56)
- **capstone** — the final project of a course: the running example finished end to end, proven with tests and real-model evidence, and handed over with a design note (lesson 60)
- **cascade (escalation)** — retrying a request on a stronger model when the cheaper one fails, inside the same budget (lesson 54)
- **case study** — a team's published account of how it built or ran a system, read for a mechanism you can test in your own system, not as a recipe (lesson 58)
- **cassette** — the file (YAML here) that holds recorded HTTP requests and responses, replayed in later test runs; vcrpy's name for it (lesson 47)
- **changelog triage** — sorting each line of a vendor changelog into act (breaking, deprecated, removed), read (features, topics you depend on) or skip (chores, docs, internal) (lesson 59)
- **chaos drill** — breaking a dependency on purpose and checking the system before, during and after the failure (lesson 15)
- **chat loop** — a loop that reads a user line, appends it to the history, sends the history to the model, appends the reply and repeats until the user quits (lesson 06)
- **checkpoint** — a lesson where you build something from everything in the Part so far, with requirements, a test and a reference solution (lesson 06)
- **chunk** — one piece of a streamed reply; in Gemini a full response object holding only the new text (lesson 11)
- **circuit breaker** — a guard that stops calling a failing backend after a run of failures, waits a cooldown, then lets one trial call decide whether to resume (lesson 57)
- **client-side history** — your code keeps every turn and resends it each call, as in lesson 08; also what `client.chats` does (lesson 09)
- **client-side rate limiter** — a token bucket in your own code, shared by every caller, that paces requests just below the provider's limit so it never returns 429 (lesson 38)
- **cold start** — the time a local runner spends loading weights into memory before the first reply; later calls skip it while the model stays loaded (lesson 16)
- **compaction** — replacing the older part of a chat with a short summary while keeping the latest turns word for word, so the history stays under a token budget (lesson 32)
- **compaction trigger** — the token count at which compaction runs, set below the budget so the request that follows still fits (lesson 32)
- **concurrency limit** — the most conversations or calls allowed in flight at once, e.g. enforced with a semaphore (lesson 38)
- **configuration** — one choice of the settings under test in a benchmark, here a model id plus a reasoning-effort level, written `model/LEVEL` (lesson 45)
- **confused deputy** — a program that uses its own permissions on behalf of someone who should not have them, e.g. an agent writing a file because a note told it to (lesson 51)
- **constrained decoding** — at each step the server removes every token that would break the schema before sampling, so the output always fits it (lesson 20)
- **content block** — one typed piece of a message, such as `{"type": "text", "text": ...}`; images, tool calls and tool results are other block types (lesson 10)
- **context engineering** — choosing, for each model call, the smallest set of tokens that lets the model do the next step: what goes in, in what order, and what stays out (lesson 31)
- **context overflow error** — the API's refusal of a request whose input is over the model's window, e.g. Gemini's 400 `INVALID_ARGUMENT` "The input token count exceeds the maximum number of tokens allowed" (lesson 32)
- **context rot** — model accuracy and recall get worse as the number of tokens in the context grows, even below the limit (lesson 05)
- **context rot test** — plant facts early in a long chat, ask about them late, and score the answers against the tokens sent; rerun it whenever context handling changes (lesson 32)
- **context window** — the most tokens a model can handle in one request: system prompt, history, new input and the output it writes, including thinking (lesson 05)
- **context window exceeded** — a request that does not fit: usually a 400 error ("prompt is too long"), or a reply stopped early (lesson 05)
- **conversation history** — the list of messages your code keeps and resends each turn; it is the only memory a chat has (lesson 06)
- **cooldown (breaker)** — how long an open circuit breaker keeps a backend out of rotation before the next trial call (lesson 57)
- **coroutine** — what calling an `async def` function returns: paused work that runs only when awaited or scheduled on the event loop (lesson 25)
- **cost-latency-quality trade-off** — no model is best at price, speed and answer quality at once; pick the cheapest, fast-enough model that passes a written check for the task (lesson 17)
- **count_tokens** — a provider call that returns how many input tokens a request would use, without generating; Gemini's is `client.models.count_tokens` (lesson 12)
- **cumulative chat cost** — the running total over a conversation; because history is resent, it grows roughly with the square of the number of turns (lesson 12)
- **daily budget** — a limit on one user's (or tenant's) spend per UTC day; each run gets the smaller of its own limit and what is left today (lesson 54)
- **data residency** — data is stored and processed only in a chosen region; on Vertex AI, a `location` that is not `global` (lesson 50)
- **data retention** — how long a provider keeps stored requests and replies (Gemini interactions: 55 days paid, 1 day free; OpenAI responses: 30 days) (lesson 09)
- **data-first ordering** — putting long input data at the top of a prompt and the instructions or question at the end (lesson 19)
- **dated price table** — per-model prices per million tokens with the date each became valid, plus when and where someone last checked them (lesson 17)
- **dated tool type** — a server-tool `type` string ending in a date, such as `web_search_20260209`, that pins the tool's behaviour; new behaviour gets a new date (lesson 44)
- **deprecation** — a vendor's announcement that a model will stop working; it still answers until its retirement date (lesson 53)
- **design note** — a short, versioned record of a system's decisions, each with its source, its date and a check that shows it still holds (lesson 58)
- **deterministic test** — a test that gives the same result on every run, because nothing in it is random, timed or remote (lesson 46)
- **developer role** — OpenAI's name for system-level instructions (a `developer` message or the `instructions` parameter); same rank as a system prompt (lesson 08)
- **disable parallel tool use** — asking the model for at most one tool call per turn: Anthropic `disable_parallel_tool_use`, OpenAI `parallel_tool_calls=false`, Gemini only by instruction (lesson 25)
- **dispatch table** — a dict from tool name to function, used to run the tool the model named (lesson 27)
- **duplicate side effect** — the effect of one intended tool call applied twice, usually because a retry or a restart repeated it (lesson 39)
- **encoding (tiktoken)** — a named, trained tokenizer such as `o200k_base` or `cl100k_base` (lesson 03)
- **end of turn** — a model reply with no tool calls: the final answer, and the normal way the agent loop ends (lesson 26)
- **end token** — a special token that marks the end of a text; when the model picks it, generation stops (lesson 02)
- **environment variable** — a named value the operating system gives a running process; read with `os.environ`; `load_dotenv` fills it from a `.env` file (lesson 07)
- **error as observation** — a tool failure is caught and sent back to the model as the tool's result, so the model can change its next call instead of the run crashing (lesson 28)
- **error result** — a tool result marked as a failure, carrying a short message (exception type and text, no stack trace) (lesson 28)
- **eval** — a fixed set of inputs plus a checker that scores a model's outputs, used to compare prompts or models (lesson 19)
- **event loop** — the asyncio scheduler that runs coroutines and switches between them whenever one is waiting (lesson 25)
- **exfiltration** — getting data out to an attacker, e.g. in a fetched URL or a rendered markdown image (lesson 51)
- **exit test** — a checkpoint's final demonstration; in lesson 18, showing that forgetting comes only from what is in the request: history not resent, or trimmed to fit the window (lesson 18)
- **exponential backoff** — waiting `base x 2^attempt` seconds after each failed attempt, up to a cap (lesson 14)
- **fail closed** — when unsure (a new tool, a typo, a missing decision), deny rather than allow (lesson 52)
- **failure taxonomy** — sorting every failure into a few groups (transient, fatal, broken stream, truncated), each with one correct action (lesson 15)
- **fake model** — a scripted Python function that stands in for a real model, so the loop runs and tests without a key (lesson 01)
- **fallback route** — the route for requests no other route fits, so an unmatched request gets a safe reply instead of an error (lesson 33)
- **few-shot examples** — a handful (3 to 5) of sample inputs with correct outputs placed in the prompt, so the model copies the pattern (lesson 19)
- **field validator** — a `@field_validator` method on a Pydantic class that checks or changes one field and raises `ValueError` to reject it (lesson 21)
- **finish reason** — Gemini's name for the stop reason: why the model stopped writing (`STOP`, `MAX_TOKENS`, ...) (lesson 07)
- **forced tool call** — a tool call the model had to make because tool_choice was any/required or named the tool; it cannot answer in text on that turn (lesson 24)
- **freeze (in code)** — a mode in which the agent is given no tools that change anything, enforced by the tool runner rather than by an instruction in the prompt (lesson 58)
- **frontier table** — a dated list of recent vendor changes, each with its source, the lessons and system parts it affects, and a probe (lesson 59)
- **function_call item** — an OpenAI Responses item for a tool call: `call_id`, `name`, `arguments` as a JSON string; Gemini Interactions has a `function_call` step with `id`, `name`, `arguments` object (lesson 23)
- **function_call_output** — the OpenAI Responses input item that returns a tool's output, linked by `call_id` (lesson 23)
- **function_result step** — the Gemini Interactions input step that returns a tool's output, linked by `call_id` to a `function_call` step's `id` (lesson 23)
- **gate** — a plain code check between two chain steps that stops the chain when an output breaks a rule (lesson 33)
- **GGUF** — the single-file model format from llama.cpp that Ollama and LM Studio load (lesson 16)
- **golden set** — a fixed list of inputs with known right answers, kept in version control and reused for every eval run (lesson 48)
- **greedy decoding** — always picking the highest-probability next token (lesson 02)
- **half-open** — the circuit-breaker state after the cooldown, where one trial call goes to the primary: success closes the breaker, failure reopens it (lesson 57)
- **hallucination** — fluent model output that states something invented or false (lesson 02)
- **hand-off contract** — the functions, return fields and tests that the next stage of a system must keep working, written down so a later change can be checked against it (lesson 60)
- **high-signal result** — a tool result holding only what helps the next step (ids, short text, totals), not a raw dump (lesson 29)
- **human in the loop** — a person must act at a set point in an automated run, e.g. before a risky tool call runs (lesson 52)
- **idempotency key** — a name for one call, sent with every attempt; the tool remembers it and answers a repeat with the saved result instead of acting again (lesson 39)
- **idempotent** — doing an operation twice has the same effect as doing it once; reading a note is, appending a line is not (lesson 39)
- **image tokens** — the input tokens a model uses to represent an image or a PDF page, billed at the normal input price; on Gemini 3 a fixed number per image or page, on Claude one per 28 x 28 pixel patch (lesson 43)
- **indirect prompt injection** — instructions planted in content an agent reads (a note, a file name, a tool result), which the model may follow as if the user wrote them (lesson 51)
- **input_json_delta** — Anthropic's stream delta type for tool arguments: a `partial_json` string appended to the call's buffer, keyed by block index (lesson 36)
- **instruction hierarchy** — the trained priority order a model follows: vendor policy, then system/developer instructions, then the user, then tool or document text; behaviour, not a guarantee (lesson 08)
- **Interactions API** — Gemini's recommended API (`client.interactions.create`, Gemini Developer API): history as `user_input`/`model_output` steps, `system_instruction`, `generation_config` (lesson 10)
- **is_error flag** — a marker on a tool result saying the tool failed: `is_error: true` on an Anthropic `tool_result`, an `"error"` key in a Gemini `FunctionResponse.response` (lesson 28)
- **jitter** — randomness added to a retry wait so clients do not retry together; full jitter picks between 0 and the backoff (lesson 14)
- **job state** — where a batch job is in its lifecycle, e.g. Gemini's `JOB_STATE_PENDING`, `RUNNING`, `SUCCEEDED`, `FAILED`, `EXPIRED` (lesson 42)
- **JSON lines** — a file with one JSON object per line; easy to append to and to read back line by line (lesson 49)
- **JSON mode** — an API setting (`response_mime_type="application/json"` on Gemini) that guarantees valid JSON but not which keys or types it holds (lesson 20)
- **JSON Schema** — a standard JSON format for describing the shape of JSON data: types, properties, required keys, allowed values (lesson 20)
- **just-in-time retrieval** — giving the model identifiers and a tool to load content when it needs it, instead of putting all the content in the prompt up front (lesson 31)
- **key fingerprint** — a short hash of a key: safe to log and compare, cannot be turned back into the key (lesson 50)
- **key rotation** — replacing a key: create the new one, deploy, check, then revoke the old one (lesson 50)
- **KV cache (outside view)** — the per-token internal state a model computes for a prompt; each token's state depends on all earlier tokens, so only an identical prefix can be reused (lesson 41)
- **latency budget** — the longest a user may wait for one answer; in a benchmark, the p95 seconds per question must stay within it (lesson 45)
- **least privilege** — giving each task only the tools and permissions it needs (lesson 51)
- **lethal trifecta** — access to private data + exposure to untrusted content + a way to communicate externally; together they let an injection steal data (Simon Willison) (lesson 51)
- **lightweight identifier** — a short reference to content (an id, title, file path or query) that stays in context in place of the content itself (lesson 31)
- **Little's law** — average items in a system = arrival rate x average time in it (L = λW), in matching units (lesson 56)
- **LM Studio** — a desktop app that runs GGUF models and serves an OpenAI-compatible API on `localhost:1234/v1` (lesson 16)
- **load test** — running many conversations at the expected concurrency to measure latency percentiles, failures and cost under load before users do (lesson 55)
- **local inference** — running a model on your own machine instead of a hosted API: no key or per-token bill, data stays local, speed depends on your hardware (lesson 16)
- **logit** — the raw score a model gives each possible next token before softmax turns it into a probability; can be negative (lesson 04)
- **loop detection** — stopping an agent run when the model makes the same tool call (same name and arguments) more than an allowed number of times (lesson 30)
- **loop fingerprint** — a hash of the loop's source code taken before and after a change, to prove the change did not touch the loop (lesson 35)
- **malformed function call** — Gemini's finish reason when a tool call could not be completed, e.g. cut off by the token limit; there is nothing to run (lesson 13)
- **managed agent** — a vendor-hosted agent: the vendor runs the loop, the tools and the session; you send tasks and read results (lesson 44)
- **max output tokens** — the limit you set on how many tokens the model may write in one reply (`max_tokens`, `max_output_tokens`); thinking tokens count toward it (lesson 05)
- **max_tokens truncation** — a reply stopped by the output limit; the text is real but unfinished (lesson 13)
- **measured baseline** — the numbers (pass rate, cost and seconds per run) a later version must keep or beat, recorded at hand-off (lesson 60)
- **media resolution** — Gemini 3's per-part setting (low, medium, high, ultra high) that fixes how many tokens an image or PDF page gets: 280 / 560 / 1,120 / 2,240 per image (lesson 43)
- **merge (BPE)** — one learned rule "glue piece a and piece b into ab"; a BPE tokenizer is an ordered list of merges (lesson 03)
- **message-list validity** — the rules a history must follow to be accepted: not empty, known roles, system first, no empty text, last message from the user (lesson 08)
- **Messages API** — Anthropic's chat API (`client.messages.create`): top-level `system`, `user`/`assistant` messages of content blocks, required `max_tokens` (lesson 10)
- **mid-stream failure** — an error after the server already answered 200 and started streaming; SDK retries do not cover it (lesson 15)
- **migration diff** — old and new model run on the same eval, compared on accuracy, wrong and missed refusals, tool calls, tokens and cost, not accuracy alone (lesson 53)
- **MIME type** — a label for a file's format, such as `image/png` or `application/pdf`, sent with the bytes so the model knows how to read them (lesson 43)
- **minted id** — a tool-call id the adapter makes up when the backend (Ollama's native API) returns tool calls without one, so results can still be paired by id (lesson 37)
- **model family** — one vendor's models of the same kind in several sizes (for Gemini: flash-lite, flash, pro); bigger is usually smarter, slower and more expensive (lesson 17)
- **model lifecycle table** — every pinned model id with its stage, retirement date and the source it was read from, checked at startup (lesson 53)
- **model pinning** — fixing an exact model id (not a `-latest` alias) in one config place, so behaviour and cost change only when you change it (lesson 17)
- **model routing (small model first)** — sending easy requests to a cheap model and only hard ones to a dearer one, to cut the average cost per run (lesson 54)
- **model_version** — the Gemini response field naming the model that actually answered; compare it with the id you pinned (lesson 17)
- **monotonic clock** — a clock that only moves forward (`time.monotonic()`), safe for measuring durations even when the system time is corrected (lesson 30)
- **multimodal input** — a request whose parts include images, PDFs, audio or video, not only text; each part is bytes plus a MIME type (lesson 43)
- **next-token prediction** — the one job of a language model: given the text so far, give a probability to every possible next token (lesson 02)
- **nucleus sampling** — another name for top-p sampling (lesson 04)
- **Ollama** — a local model runner: a CLI plus a server on `localhost:11434` with its own API and an OpenAI-compatible `/v1` (lesson 16)
- **open to new tools** — a loop that gets a new tool by registering a function, with no change to the loop's code (lesson 35)
- **open-weight model** — a model whose trained weights you can download and run yourself (lesson 16)
- **OpenAI-compatible endpoint** — a server that accepts OpenAI's request format, so the `openai` SDK works with it by changing `base_url` (lesson 16)
- **OpenTelemetry GenAI conventions** — shared attribute names for model and tool calls (`gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.tool.name`, ...), so any tracing tool can read them (lesson 49)
- **oracle routing** — the cost of sending each question to the cheapest configuration that got it right; an upper bound on what routing could save (lesson 45)
- **outage drill** — a chaos drill that takes a provider down for a time window and compares errors and latency before, during and after (lesson 57)
- **p50 / p95 / p99** — latency percentiles: the time within which 50 %, 95 % or 99 % of requests finish (lesson 38)
- **pagination** — returning results one page at a time with a total and a next-page marker, so the model asks for more only when needed (lesson 29)
- **parallel tool calls** — several tool calls in one model reply, each with its own tool call id; all their results go back in one message (lesson 25)
- **parallelisation** — running model calls that do not depend on each other at the same time, so they finish in one round (lesson 34)
- **parse helper** — an SDK feature that takes a class (e.g. a Pydantic model), sends its schema and returns a typed object (`resp.parsed` in google-genai) (lesson 20)
- **partial JSON** — an unfinished JSON string from a stream; not valid until the last piece arrives, so parse only once the call is complete (lesson 36)
- **partial JSON parser** — a parser that turns unfinished JSON into the best object so far (`jiter.from_json(..., partial_mode=...)`); for previews, never for running tools (lesson 36)
- **partial_args** — Gemini's (Vertex AI) streamed tool arguments: values tagged with a JSON path like `$.text`, with `will_continue` while more is coming (lesson 36)
- **pass rate** — the share of all eval runs that passed (lesson 48)
- **pass@k** — the chance that at least one of k runs of an eval case passes (lesson 48)
- **pass^k** — the chance that all k runs of an eval case pass; the stricter number for agents that run unattended (lesson 48)
- **path traversal** — escaping a folder with names like `../x` or absolute paths; lesson 28 stops it by accepting only a plain file name (`Path(name).name == name`) (lesson 28)
- **pause_turn** — Anthropic stop reason: a server-run tool loop paused at its limit; send the reply back to continue (lesson 13)
- **PDF input** — sending a PDF as a part; each page is read as an image, and on Gemini 3 its native text is extracted and not billed (lesson 43)
- **per-call timeout** — a limit on one model request (`types.HttpOptions(timeout=ms)` in google-genai), so a hung call raises instead of blocking the loop (lesson 30)
- **per-environment keys** — a separate key, workspace or project and spend cap for dev, staging and prod (lesson 50)
- **PII redaction** — replacing personal data (emails, phone numbers) and secrets with placeholders before a log line is written (lesson 49)
- **pinned run** — a run that stays on the backend it failed over to until it ends, because vendor-only state (Gemini's `raw` turn, call ids) does not transfer mid-run (lesson 57)
- **planted bug** — a deliberate one-line change to the code under test, to prove the tests notice it (lesson 46)
- **poka-yoke** — designing a tool so misuse is impossible or harmless, e.g. clamping a page size or refusing to overwrite a file by default (lesson 29)
- **post-mortem** — a written account after an incident: what happened, why, why it was not caught sooner, and what changes; "blameless" when it looks for causes in the system, not the people (lesson 58)
- **prefill** — starting the model's reply for it with a final assistant turn; rejected with a 400 error on Claude 4.6 and later (lesson 19)
- **preflight call** — one cheap request with the full production settings to a new model, to catch rejected settings (such as an unsupported thinking level) before an eval (lesson 53)
- **previous_interaction_id** — the Gemini Interactions API parameter that continues from a stored interaction; OpenAI's Responses API equivalent is `previous_response_id` (lesson 09)
- **price per million tokens (per MTok)** — how providers quote prices, separately for input and output; cost = tokens × price / 1,000,000 (lesson 12)
- **probe** — a small offline check that a claim about an SDK still holds in the installed version: a method exists, a field accepts a value, a client sits on a given HTTP library (lesson 59)
- **production canary eval** — a small golden set run on a schedule against the live system, alerting on failures; catches a break hitting a share p of requests with probability 1 - (1 - p)^n (lesson 58)
- **prompt caching** — the provider reuses the work done on the start of a recent request when a new one begins with exactly the same tokens, and bills those tokens at a fraction of the input price (lesson 41)
- **prompt chaining** — splitting a task into a fixed sequence of model calls, each one reading the previous call's output (lesson 33)
- **prompt engineering** — writing and testing the text you send a model so its output is reliably what your code needs (lesson 19)
- **provider adapter** — a class implementing the agent's `model(messages, tools)` call for one backend: a request half (neutral → vendor) and a reply half (vendor → neutral) (lesson 37)
- **provider fallback (failover)** — sending a model call to a second backend when the first has a provider-side failure (5xx, 429, timeout), behind the same adapter contract (lesson 57)
- **provider-neutral messages** — the app's own message shape (`user`, `assistant` with `text` or `tool_calls`, `tool` with `call_id`) that adapters convert to and from each vendor's format (lesson 37)
- **Provisioned Throughput** — capacity bought in advance from Vertex AI for a strict SLA, paid whether used or not (lesson 56)
- **Pydantic validation** — checking data against a Pydantic class's types and rules; failures raise one `ValidationError` listing every broken rule (lesson 21)
- **pytest** — the standard Python test runner: it collects `test_*` functions from `test_*.py` files and reports each failing `assert` (lesson 46)
- **quality floor** — the minimum success rate a configuration must reach before its cost or speed counts; set before looking at the results (lesson 45)
- **quantisation** — storing weights as small integers plus scales (about 4 bits instead of 16) so a model needs far less memory, at a small cost in accuracy (lesson 16)
- **rate limit** — a provider's cap on requests or tokens per time window; exceeding it returns HTTP 429 (lesson 14)
- **rate-limit tier** — a provider's level of limits (TPM, RPM) for an account, usually earned by past spend (lesson 56)
- **reasoning effort** — the setting that controls how much a model thinks before answering: Gemini `thinking_level`, Anthropic `effort`, OpenAI `reasoning.effort`; it replaced fixed thinking budgets (lesson 40)
- **record and replay** — testing against a real API by saving its HTTP traffic once and serving later runs from the saved copy (lesson 47)
- **record mode** — vcrpy's rule for real calls: `"none"` only replays, `"all"` records every call, `"once"` records only if the cassette is missing (lesson 47)
- **refusal** — the model declines to answer; Anthropic reports `stop_reason: "refusal"` (lesson 13)
- **release gate** — a fixed list of checks with thresholds, each fed by a measurement (tests, evals, attacks, load, cost, logs), that answers "ship" only if every check passes (lesson 55)
- **renormalise** — divide the kept probabilities by their total so they add up to 1 again (lesson 04)
- **repeated runs** — running each eval case several times, because a sampling model can answer the same question differently each time (lesson 48)
- **replayed load** — a load test where each conversation plays back a recorded real model run (replies, tokens, seconds), so your own stack runs for real at volume without paying the provider; it shows your own queueing only, since real provider latency can rise under load (lesson 55)
- **request adapter** — a small function that converts an app's own message format into one vendor's request format; compare *provider adapter* (lesson 37) (lesson 10)
- **request id** — the provider's id for one API call, used for support tickets and log searches (lesson 13)
- **request key (custom_id)** — your own id on each batched request, used to match results, which can come back in any order (lesson 42)
- **request matching** — the fields (`match_on`: method, host, path, body, ...) that decide which recorded response answers a new request (lesson 47)
- **request trimming** — dropping the oldest user/assistant pairs from the request (not from the stored history) until it fits the window minus the reserved output (lesson 18)
- **response object** — what an API call returns: the reply text plus metadata such as model version, id, finish reason and usage (lesson 07)
- **Responses API** — OpenAI's current API (`client.responses.create`): a list of `input` items, rules as a `developer` message or `instructions`, `max_output_tokens` (lesson 10)
- **resume** — reload a run's checkpoint, run the tool calls that still have no result (with their original keys), and continue the loop (lesson 39)
- **retirement** — the date after which calls to a model id fail (lesson 53)
- **retirement calendar** — the dated list of model and API shutdowns a system depends on, checked on a schedule with a warning window (lesson 59)
- **retry before first chunk** — retrying a streamed call only while nothing has been shown; after that, a retry would repeat text the user has already seen (lesson 18)
- **retry cap** — the maximum number of attempts before a retry loop gives up and raises, bounding cost and time (lesson 21)
- **retry-after** — a response header giving the seconds to wait before retrying (lesson 14)
- **role** — the label on each message saying who wrote it: `user`, `model` (Gemini) or `assistant` (most vendors), or `system`/`developer` (lesson 08)
- **role prompt** — a line, usually in the system instruction, that tells the model who it is and whom it works for (lesson 19)
- **round** — a group of model calls that wait for nothing but each other; wall time grows with rounds, not with calls (lesson 34)
- **routing** — classifying a request once and sending it to the handler built for that kind of request (lesson 33)
- **RPM / TPM** — requests per minute and tokens per minute, the units of rate limits (Anthropic splits TPM into ITPM and OTPM) (lesson 14)
- **run budget** — a limit on the dollars and tokens one agent run may use, checked before each model call with the worst case of that call (lesson 54)
- **run checkpoint** — the run id and message list saved to disk after every step, so a killed run can continue instead of starting over (lesson 39)
- **run id** — an id your code makes once per agent run and puts on every event of that run (lesson 49)
- **safe evaluation** — computing a model-supplied expression by walking its syntax tree with an allow-list of operations, never `eval` (lesson 29)
- **safety block** — the provider withholds a prompt (`prompt_feedback.block_reason`) or a reply (finish reason `SAFETY` and similar); `.text` is `None` (lesson 13)
- **sampling** — picking the next token at random, weighted by its probability, instead of always the top one (lesson 04)
- **schema from type hints** — building a tool's JSON Schema from a Python function's parameters, type hints, defaults and docstring instead of writing it by hand (lesson 27)
- **schema subset** — the part of JSON Schema a vendor's structured output supports; keywords outside it are rejected, and the subset differs per vendor (lesson 20)
- **scorer** — code, a model or a person that marks one output pass or fail against the golden answer (lesson 48)
- **SDK client** — the vendor library object (e.g. `genai.Client`) that holds your key and settings and turns Python calls into HTTP requests (lesson 07)
- **SDK helper** — a function in the vendor's client library that runs the tool loop for you on your machine; same loop, less code, less visibility (lesson 44)
- **secret manager** — a service that stores keys encrypted, controls who reads them, and injects them into apps (lesson 50)
- **secret scanning** — searching files and Git history for key-shaped strings, in a pre-commit hook and in CI (lesson 50)
- **secret scrubbing** — removing keys, tokens, cookies and private data from a recording before it is saved (lesson 47)
- **sectioning** — splitting one task into independent parts, running them in parallel, and joining the results in code (lesson 34)
- **semaphore (`asyncio.Semaphore`)** — a counter of free slots: `async with sem` takes a slot, waits if none is free, and gives it back on exit (lesson 38)
- **server-sent events (SSE)** — an HTTP response that stays open and sends `data: ...` lines, one event per blank-line-separated block; content type `text/event-stream` (lesson 11)
- **server-side state** — the provider stores the conversation and you continue it by sending an id plus the new message, instead of the whole history (lesson 09)
- **server-side tool** — a tool the vendor runs on its own machines inside your API request (web search, code execution, tool search, MCP connector); you see the result, not the run (lesson 44)
- **sliding window (truncation)** — dropping the oldest messages so the rest fits; done by apps or by you, not by most APIs by default (lesson 05)
- **softmax** — turns logits into probabilities: exp of each score divided by the sum of all of them (lesson 04)
- **spend cap** — a monthly spending limit; Anthropic returns 429 `enforced_spend_limit_reached` with no retry-after, so retrying is futile (lesson 14)
- **spend limit** — a provider-side cap on an account's spend (Gemini project cap, Anthropic tier or workspace limit); when it is hit every call fails until it resets; see spend cap (lesson 54)
- **stable prefix** — the start of a request that stays identical from call to call (system prompt, tool schemas, early history); keeping it stable lets providers reuse it (lesson 31)
- **stale cassette** — a recording that no longer matches the code or the live API, so tests pass while production fails (lesson 47)
- **stateless API** — the stateless-model property seen from the API side: the API keeps nothing between requests; each reply depends only on what is in that request (lessons 06, 08)
- **stateless model** — a model whose reply depends only on the messages in the current request; it remembers nothing between calls (lesson 06)
- **step** — one pass of the agent loop: one model call plus the tools it asked for (lesson 26)
- **step limit** — the most steps (`max_steps`) the agent loop may take before it stops without an answer and reports `stop="step_limit"` (lesson 26)
- **stop condition** — the rule that ends generation: end token, max_tokens limit, or a stop sequence (lesson 02)
- **stop reason** — why a reply ended (`end_turn`, `max_tokens`, `stop_sequence`, `tool_use`, `pause_turn`, `refusal`); Gemini calls it finish reason (lesson 13)
- **stop sequence** — a text given in advance; generation stops when it appears, and it is left out of the output (lesson 02)
- **stopping condition** — a rule that ends the agent loop (end of turn, step limit, timeout, repeated call, cancel); the run reports which one as `stop` (lesson 30)
- **store=False** — the request flag that tells the provider not to keep the turn; it also means you cannot chain from it (lesson 09)
- **stream event** — one typed message in a streamed reply, such as Anthropic's `content_block_start`, `content_block_delta`, `content_block_stop` and `message_delta` (lesson 36)
- **streaming** — receiving a model's reply in small pieces while it is still being generated, instead of all at once at the end (lesson 11)
- **strict tool schema** — a tool schema the provider enforces while generating, so arguments always match; needs `additionalProperties: false` and (OpenAI) every field in `required` (lesson 24)
- **structured logging** — writing each event as named fields (here JSON) instead of a sentence, so programs can filter, sum and sort the log (lesson 49)
- **structured output** — model output in a machine-readable shape (here JSON) that code can use directly (lesson 20)
- **subword token** — a token that is part of a word; rare words are split into several of them (lesson 03)
- **summarisation** — asking a model (or code) to rewrite many turns as a short text that keeps what later turns need (lesson 32)
- **system instruction** — the developer's standing rules for the model, sent with every request outside the chat turns; Gemini `system_instruction`, Anthropic `system` (lesson 08)
- **tail latency** — the slow end of the latency distribution (p95, p99), which the mean hides (lesson 38)
- **taint rule** — once untrusted content has entered the context, deny tools that talk to the outside for the rest of the run (lesson 51)
- **temperature** — divides logits before softmax; below 1 sharpens the distribution, above 1 flattens it; 0 means greedy (lesson 04)
- **test isolation** — each test builds its own fakes and data, so tests pass or fail the same alone or together, in any order (lesson 46)
- **thinking block** — Anthropic's content block (`type: "thinking"`, `thinking`, `signature`) holding a reply's reasoning; send it back unchanged within a tool-use turn (lesson 40)
- **thinking block preservation** — sending a model's thinking state (Gemini thought signatures, Anthropic thinking blocks, OpenAI reasoning items) back unmodified on the next call of a tool loop (lesson 40)
- **thinking tokens** — hidden reasoning tokens a reasoning model writes before its answer; they use the output budget and are billed as output (lesson 05)
- **thought signature** — an opaque field Gemini 3 attaches to function-call parts; send the model's turn back unchanged or the request fails with a 400 (lesson 22)
- **thought summary** — a readable summary of a model's hidden thinking, returned only on request (`include_thoughts=True` on Gemini, `display: "summarized"` on Anthropic); never the raw reasoning (lesson 40)
- **throughput** — work finished per unit of time, e.g. conversations per second of wall time (lesson 38)
- **thundering herd** — many clients retrying at the same moment and overloading the server again (lesson 14)
- **time to first token (TTFT)** — the time from sending the request to receiving the first piece of the reply; what users feel as waiting (lesson 11)
- **timeout** — the longest you wait for a response before treating the call as failed (lesson 14)
- **token** — the unit of text a model reads and writes (lesson 02 uses words and punctuation; lesson 03 shows real tokenizers) (lesson 02)
- **token bucket** — a rate limiter that refills continuously, so bursts can be rejected below the per-minute limit (lesson 14)
- **token id** — the number for a token in the vocabulary; models read and write ids, not text (lesson 03)
- **tokenizer differences** — each model family (and sometimes each version) has its own tokenizer, so the same text has different token counts (lesson 03)
- **tokens by modality** — Gemini's `usage_metadata.prompt_tokens_details`, splitting input tokens into TEXT, IMAGE and other kinds (lesson 43)
- **tokens per second** — how fast the model writes once it has started: output tokens divided by the time from first to last chunk (lesson 11)
- **tool** — an ordinary function your code runs when the model asks for it by name with arguments (lesson 01)
- **tool call** — a model reply that asks your code to run a named tool with given arguments; the model runs nothing itself (lesson 22)
- **tool call id** — the id the model gives each tool call; the matching tool result must carry the same id (not lesson 13's call id) (lesson 22)
- **tool design** — shaping a tool for the model as its user: one job, a clear name and description, narrow inputs, small results, actionable errors (lesson 29)
- **tool permission matrix** — a table of which tools, with which arguments, each task may call; everything else is denied (lesson 51)
- **tool registry** — one object that holds every tool's function and schema; tools are added with a decorator and the loop reads from it, so adding a tool needs no loop change (lesson 27)
- **tool result** — the message your code sends back with a tool's output, tagged with the tool call id it answers (lesson 22)
- **tool runner** — Anthropic's beta SDK helper (`client.beta.messages.tool_runner` with `@beta_tool` functions) that runs the tool loop up to `max_iterations` (lesson 44)
- **tool schema** — the description of a tool sent to the model: name, description and a JSON Schema for its arguments; Gemini calls it a FunctionDeclaration (lesson 22)
- **tool-definition token cost** — the input tokens every tool schema adds to every model call, whether or not the tool is used (lesson 29)
- **tool-result trimming** — replacing old tool results in the request with a short placeholder, while keeping the tool calls and the full stored history (lesson 31)
- **tool_choice** — the request setting that says whether the model may, must or must not call a tool: auto, any/required, a named tool, or none (lesson 24)
- **tool_result block** — an Anthropic content block in a `user` message carrying a tool's output, linked by `tool_use_id`; must come first in that message, right after the call (lesson 23)
- **tool_use block** — an Anthropic content block in an `assistant` message asking for a tool: `id`, `name`, `input` (lesson 23)
- **top-k** — keep only the k most likely tokens, renormalise, then sample (lesson 04)
- **top-p** — keep the smallest set of most likely tokens whose probabilities add up to at least p, renormalise, then sample; also called nucleus sampling (lesson 04)
- **trace** — all the events of one run, tied together by its run id (lesson 49)
- **transcript debugging** — finding why a run went wrong by querying its trace file, not by rerunning it (lesson 49)
- **truncated tool JSON** — tool arguments cut off because `max_tokens` ran out (`stop_reason: max_tokens`); retry with a larger budget instead of parsing (lesson 15)
- **truncation (tool results)** — cutting a result past a size limit and saying so in the result, with how to ask for less (lesson 29)
- **turnaround time** — how long a batch job takes from submission to results; providers document targets (24 h) and expiry limits, not guarantees (lesson 42)
- **unit test** — a small, fast test of one piece of code (here the loop) with everything around it, such as the model, replaced by fakes (lesson 46)
- **untrusted-content placement** — keeping tool output inside tool results and marked as data, never mixed into instructions (lesson 51)
- **usage accounting** — reading the token counts each response reports (input, output, thinking) and turning them into cost per turn and per conversation (lesson 12)
- **usage fields** — the token counts a response reports (input, output, thinking, total); the basis of cost (lesson 07)
- **`VALIDATED` mode** — Gemini's function-calling mode that keeps tool arguments to the declared schema while still allowing a text answer (lesson 24)
- **validation context** — extra data passed with `model_validate_json(..., context=...)` that validators read as `info.context`, e.g. the source note (lesson 21)
- **validation retry** — sending the model its invalid reply plus the validation errors and asking again (lesson 21)
- **ValidationError** — Pydantic's exception; `.errors()` gives one dict per problem with `loc`, `type`, `msg` and `input` (lesson 21)
- **vendor lock-in** — when changing model provider means rewriting the app, because one vendor's formats or SDK objects have spread through its code (lesson 37)
- **vocabulary** — the fixed list of tokens a tokenizer knows, each with a number (token id) (lesson 03)
- **vote threshold** — how many voters must agree (for example 2 of 3); a higher threshold means fewer false passes and more false alarms (lesson 34)
- **voting** — running several checks or attempts on the same input and combining their answers with a rule such as a majority (lesson 34)
- **wall-clock timeout** — a limit on the real time a whole agent run may take, checked between steps (lesson 30)
- **workflow** — an LLM system whose steps are fixed in code; the model fills in each step but does not choose the next one (lesson 33)
- **workspace (Anthropic)** — a group in an Anthropic organisation with its own keys, spend limit and rate limits (lesson 50)
- **worst-case turn cost** — exact input cost plus `max_output_tokens` at the output price; an upper bound you can check before sending (lesson 12)
- **XML tags (in prompts)** — labels like `<note>` and `<example>` that mark where each part of a prompt starts and ends (lesson 19)
- **zero data retention** — the provider keeps no prompts or replies; on Vertex it takes several settings, not one flag (lesson 50)
