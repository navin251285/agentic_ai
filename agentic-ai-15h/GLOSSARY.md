# Glossary

Terms used in the 15-hour course (lessons 01–37). Each entry names the lesson that teaches it.

- **A2A** — the Agent2Agent protocol: a standard way for one agent to discover and hand a task to another agent (lesson 27)
- **Actionable error** — a tool error that names the bad field or the missing fact and gives the next step, so the model can recover without a human (lesson 07)
- **activity (Temporal)** — one step of a durable run that does outside work (a charge, a receipt). The server records its result, and retries it after a lost worker (lesson 35)
- **Agent** — a model plus tools plus instructions, run in a loop: the model picks the next tool, your code runs it, and the loop ends with an answer (lesson 01)
- **Agent card** — the JSON description an A2A agent publishes at a well-known URL: its name, skills, endpoint and auth, so another agent can find it (lesson 27)
- **Agent loop** — the repeated cycle of model decision, tool call, tool result and model decision again, until the model answers or a cap stops it (lesson 01)
- **approval gate** — a check that holds every write until a person approves it, so the real arguments are seen before anything changes (lesson 09; built with interrupt and resume in lesson 14)
- **Audit log** — a record of who did what, on whose behalf, and who approved each money move. It holds counts and names, never customer text (lesson 31)
- **automatic function calling** — the vendor SDK runs the tool the model asks for, sends the result back and returns the final answer; the hand loop turns this off and does the steps itself (lesson 20)
- **Backoff and jitter** — waiting longer after each failed try (exponential backoff), with a random extra part so many clients that failed together do not retry at the same moment (lesson 02)
- **call_id** — the id OpenAI gives one function-call request; the matching `function_call_output` item carries the same id (lesson 05)
- **Capstone** — a lesson that puts the parts of a course into one working service and checks it with real results (lesson 37)
- **Chatbot** — a model call with no tools and no loop: it answers from its words alone (lesson 01)
- **checkpoint** — a lesson that puts the parts of a Part together into one working artifact and checks it with one command before the next Part starts (lesson 10)
- **Citation** — a pointer from an answer back to the source chunk it came from, so a reader can check the claim (lesson 18)
- **Context window** — the total room in one model call for input, thinking and output together (lesson 03)
- **Data residency** — the rule about where personal data is stored and processed; a region can be up and still break it (lesson 36)
- **Distillation** — training a small model on the outputs of a large model (lesson 03)
- **durable execution** — a run whose finished steps are recorded outside the process, so another worker resumes it after a crash (lesson 35)
- **Embedding** — a list of numbers that places a piece of text near similar text, so a search can find meaning rather than exact words (lesson 17)
- **EU AI Act** — the EU's binding AI law with risk tiers; its 2026 Digital Omnibus moved some dates, so check EUR-Lex (lesson 36)
- **event history** — the server's ordered record of a durable run's events; a new worker rebuilds the run from it (lesson 35)
- **Fine-tuning** — further training of a model on your own examples, which changes its weights (lesson 03)
- **Golden set** — a list of tasks where the right answer is known in advance: the request and the expected end state, not the wording of a reply (lesson 08)
- **hand loop** — the agent loop you write yourself around the model SDK: you call the model, run the tools, decide when to stop (lesson 20)
- **Idempotency key** — an id sent with a payment or write so that a retry returns the first answer instead of acting twice (lesson 32)
- **indirect prompt injection** — instructions hidden in data the agent fetches (a ticket, email, web page or tool result), which the model may read as commands (lesson 09)
- **interrupt()** — a LangGraph call inside a node that pauses the run, saves its state, and returns a value when the run is resumed (lesson 19; the approval gate is lesson 14)
- **interrupt_before** — a LangGraph compile option that stops a run before a named node runs and saves the state, so the next step can wait (lesson 20)
- **ISO/IEC 42001** — the international AI management-system standard; an organisation can be certified against it, not one agent (lesson 36)
- **JSON Schema** — the standard format that describes a tool's arguments (names, types, required fields); the model reads it before it writes a call (lesson 07)
- **Kill drill** — a planned failure, such as a SIGKILL on a replica under load, with the checks written down before it runs (lesson 34; the worker version is lesson 35)
- **least privilege** — giving each tool and agent only the scopes its job needs, enforced in code, so a refused call never runs (lesson 09)
- **Lethal trifecta** — the three conditions that make prompt injection serious: the agent reads untrusted input, can reach private data, and can send data out (lesson 30)
- **LLM-as-judge** — a second model call that grades an answer against a rubric, so grading can scale past what a person reads (lesson 22)
- **Logits** — the raw scores a model gives each possible next token, before softmax turns them into probabilities (lesson 03)
- **Managed agent runtime** — a cloud service that runs an agent for you, such as AgentCore Runtime or Foundry hosted agents, with a sandbox per session (lesson 36)
- **MCP** — the Model Context Protocol: a standard way for an agent to find and call tools on a server it did not write (lesson 21)
- **Message** — one entry in the list sent to a model: a role and its content (lesson 02)
- **Multi-tenancy** — one agent service serving several customers (tenants), with each tenant's data, memory, cache and tool credentials kept apart (lesson 36)
- **NIST AI RMF** — the voluntary US framework for managing AI risk, with four functions: Govern, Map, Measure, Manage (lesson 36)
- **Observation** — what your code returns to the model after a tool runs: a result, or an error with a next step (lesson 07)
- **Outcome grading** — checking the world after an agent run (a refund row exists, a ticket is open), not the words it used (lesson 08)
- **pass@k** — the chance that at least one of k runs of a task succeeds (lesson 08)
- **pass^k** — the chance that all k runs of a task succeed; the stricter measure of reliability (lesson 08)
- **prompt injection** — text that tries to override an agent's instructions; direct when the user types it, indirect when it arrives through data (lesson 09)
- **Pydantic** — a Python library whose models check data against types and your own rules, and write the JSON Schema for a tool's arguments from the same class; it raises a ValidationError when a value breaks them (lessons 04 and 07)
- **RAG** — retrieval-augmented generation: find the relevant text first, then put it in the prompt so the answer is grounded in it (lesson 17)
- **Rate limit (429)** — the API's answer "too many requests" when a per-minute or per-day quota is used up; the right reply is to wait and retry (lesson 02)
- **Registry** — a list of the agents or tools a system can find and call, with what each one does (lesson 27)
- **release gate** — a numeric check that decides whether a build ships: here, the golden-set success rate must reach 75% and no task may newly fail; the ship or hold answer comes from numbers, not opinion (lesson 10; the CI version is lesson 28)
- **Release gate** — an automatic check in CI that blocks a change when the evals fall below their bar (lesson 28)
- **Repeated-call detection** — stopping an agent loop when the model asks for the same tool with the same arguments again, instead of running it again (lesson 06)
- **Role** — who wrote a message: `user` for the person, `model` for the assistant's earlier reply in Gemini (lesson 02)
- **RPO** — recovery point objective: the most recent data you can afford to lose, as an age at the moment of failure (lesson 36)
- **RTO** — recovery time objective: the longest a service may be down after a failure (lesson 36)
- **Scripted agent** — a stand-in agent with fixed rules and no model, so a test is deterministic and makes no model call (lesson 08)
- **Span** — one timed step of a run in a trace, such as a model call or a tool call, with its attributes (lesson 29)
- **Spend cap** — the most money one task or whole run may spend, added up from the usage each model reply returns and checked before the next call so a turn stops, not overruns (lesson 06; the whole-run budget is lesson 37, the cost maths lesson 33)
- **start-to-close timeout** — the longest time one activity try may take; when it expires the server retries, which is how a lost worker is noticed (lesson 35)
- **Stateless API** — the server keeps no memory between calls, so your code resends the conversation history each time (lesson 02)
- **Step cap** — the most model calls one task may make before the loop stops (lesson 06)
- **Streaming** — receiving a model's reply in chunks as it is written, so the first words arrive early (lesson 02)
- **Structured output** — a model reply that must follow a JSON schema sent with the request, so code can read it as data instead of text (lesson 04)
- **System instruction** — the rules and role given for a whole call, sent apart from the list of messages (lesson 02)
- **Task success rate** — the share of golden tasks that pass every grade (lesson 08)
- **Temperature** — a sampling dial: low sharpens the model's scores so the top token wins more often, high flattens them so more tokens get picked (lesson 03)
- **Temporal workflow** — a durable function on the Temporal server whose steps survive a crash and resume where they stopped; not the same word as a workflow in lesson 01 (lesson 35)
- **Tenant** — one customer or organisation whose data, limits and costs are kept apart from every other customer on the same system (lesson 36)
- **Thinking level** — how much a model thinks before it answers (for Gemini `thinking_level`); thinking tokens are billed as output (lesson 03)
- **Thread id** — the id that ties together every saved state of one conversation or run, so a resumed run loads the right history (lesson 19)
- **Timeout** — the longest time to wait for one request before giving up (lesson 02)
- **Token** — a chunk of text (often a word or part of a word) that a model reads and writes one at a time; each vendor has its own tokenizer (lesson 03)
- **Tool description** — the text that says what a tool is for, when to use it and when not to; part of the prompt the model reads (lesson 07)
- **Tool name** — the identifier the model writes in a request; a specific verb-and-noun name such as `lookup_order` beats a vague one such as `lookup` (lesson 07)
- **Top-k** — the k closest chunks a search returns, for example the 5 closest to the question (lesson 17)
- **Top-p** — a sampling dial that keeps the most likely tokens whose probabilities add up to p and drops the rest (lesson 03)
- **Trace** — the record of one agent run as a tree of timed steps, from the model call down to each tool call (lesson 29)
- **Trajectory grading** — checking the path of an agent run: which tools it called, which it must not call (lessons 08 and 22)
- **turn** — one message in the conversation list sent to a model (lesson 05)
- **Usage** — the input and output token counts the API returns with every reply; the basis of the cost (lesson 02)
- **Validation retry** — sending a failed validation error back to the model with its last answer, so it corrects that value; always capped at a few tries (lesson 04)
- **vendor agent SDK** — a model vendor's own agent layer that runs the tool loop for you, such as the OpenAI Agents SDK, Claude Agent SDK or Google ADK (lesson 20)
- **worker (durable runs)** — a process that polls a task queue and runs workflow and activity code; any worker on the queue can continue a run (lesson 35)
- **Workflow** — a fixed sequence of model and code steps, where your code decides the path and the model fills in steps (lesson 01)
- **xfail (strict)** — a pytest mark for a known failure: the test is reported as expected to fail, and with strict=True it fails the suite when it starts passing (lesson 08)
- **XML tags in a prompt** — tags such as `<rules>`, `<email>` and `<example>` that mark the parts of a prompt, so the model can tell rules, data and examples apart (lesson 04)
